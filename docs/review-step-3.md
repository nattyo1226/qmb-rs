記録日: 2026-10-25

本書は Step 3 までのレビュー指摘・整理候補・設計上の確認事項を追跡する一時メモである。恒久仕様や採用済みの修正計画、新たな crate 分割の決定ではなく、対応・方針整理後に整理・削除する。恒久ドキュメントからのリンクは追加しない。

## 1. 複合内積の不要な展開

状態: 2026-10-25 に修正・検証済み。以下の指摘と測定値は修正前の記録であり、修正結果は本節末尾に記載する。

### 指摘と確認結果

優先度は P2。対象は [composite_eval.rs](../crates/qmb-core/src/expr/composite_eval.rs) の `State::inner_product`（記録時192行付近）と `StateTerms::next`。

`StateTerms` は Tensor 内の複合状態の和を分配し、内積は左右の全項の組み合わせを走査する。同じ積状態でも、各因子の二状態を配置前に加算するか、配置後に加算するかで計算量が大きく異なる。

```rust
// a と b は同一局所構造の二つの局所状態式、h は一つの因子。
let before = (&a + &b).at(&h)?;
let after = a.at(&h)?.add(&b.at(&h)?)?;
```

レビュー時、core の公開 API だけで二次元の局所代数を定義し、直交する二状態の内積呼出回数をカウンタで測定した。異なる N 因子に上記の状態を配置して Tensor を作り、その自己内積を求めた結果は次のとおり。

| 因子数 N | 配置前に加算: primitive 内積の回数 | 配置後に加算: primitive 内積の回数 | 両経路の自己内積 |
| --- | --- | --- | --- |
| 1 | 4 | 4 | 2 |
| 4 | 16 | 1,024 | 16 |
| 6 | 24 | 24,576 | 64 |
| 8 | 32 | 524,288 | 256 |

この入力では前者が `4N` 回、後者が `N × 4^N` 回となる。計算結果の不一致は確認されていないが、期待値も内積の経路を使うため影響を受ける。項を逐次生成していることだけでは、この不要な計算を避けられない。

### 修正候補と検証条件

積状態同士では対応する因子の内積を先に計算し、その積を求める経路を検討する。一般の和や異なる括り方も扱える必要があり、Tensor の子の位置だけで因子の対応を決めない。

- 配置前後の加算が同じ数学的結果になり、上記入力の処理が指数的に増えないことを呼出回数で検証する。
- 入れ子・異なる括り方、複素係数の共役、zero・unit・局所作用を含む既存の結果を維持する。
- 基底展開や行列化を必須にせず、反復的な走査・破棄と部分式の共有を維持する。

[Step 3 の実装方針](step-3-design.md)は一般の入力に対する最適な計算量を完了条件としていない。本件は特定の単純な積状態で再現した性能上の改善事項であり、その完了条件の違反と断定するものではない。

### 修正内容と検証結果

[inner_product.rs](../crates/qmb-core/src/expr/inner_product.rs) に、積として分離できる部分系の内積を先に計算する共通評価処理を実装し、`StateTerms` による大域的な項列挙を置き換えた。公開 API と数値制約、具体的代数・Index との依存関係は維持している。

最初に状態空間の Index と順序の互換性を確認する。その後、評価中だけ保持する各節点の因子数から左右に共通する部分系の境界を求め、対応する部分系の内積を掛け合わせる。和の分配は、これ以上分離できない区間に限定する。零因子空間上の scalar は独立に扱い、空の和による zero と unit を区別する。走査・縮約は作業スタックで処理し、式や primitive を複製しない。

- 配置前後の加算を含む左右4通りの内積と、局所作用による期待値について、8因子で32回、32因子で128回の primitive 内積となることを回帰テストで確認した。この入力の呼出回数は両表現とも `4N` となる。
- 異なる括り方と互いに境界が重なる複数因子の和、複素係数の共役、途中に挿入した scalar・unit、所属空間を持つ zero を検証した。
- 単精度・倍精度で独立したベクトル・行列計算と照合した。既存の三次元局所代数、最小限の数値制約、非 Clone な primitive、128 KiB スタックでの2万段の式の検証も成功した。
- `cargo test --workspace` の全73テスト（doc test を含む）、format check、Clippy、警告をエラーとするドキュメント生成が成功した。

一般の複数因子にまたがる和には必要な分配を行うため、任意の状態に対する線型時間を保証するものではない。MSRV と `std` のない target 向けビルドは今回も未検証である。

## 2. 線型結合の係数制約

状態: 2026-10-25 に workspace 全体の制約を見直して修正済み。以下の指摘は修正前の記録である。

### 指摘と確認結果

優先度は P2。対象は [linear_combination.rs](../crates/qmb-core/src/linear_combination.rs) の `LinearCombination::scaled`（記録時85行付近）。

係数の乗算に `T: Clone + Num` を要求している。実際の複素数乗算に不要な除算・剰余・比較・零・単位元などの能力まで必要になる。

レビュー時、`Clone` と `Add`・`Sub`・`Mul` を実装した係数型 `Ring` について、次の呼出しが `Ring: Num` を満たさず E0599 になることを確認した。

```rust
let terms = LinearCombination::term(Complex::new(Ring(1), Ring(0)), "ket");
let scaled = terms.scaled(Complex::new(Ring(2), Ring(0)));
```

一方、[evaluate.rs](../crates/qmb-core/src/expr/evaluate.rs) の `multiply` は `Clone + Add + Sub + Mul` だけで複素数乗算を実装している。同じ係数処理に対する制約が、線型結合と式の評価で不統一になっている。

### 修正候補と検証条件

複素数の基本演算を crate 内部の数値処理 module に切り出し、有限線型結合と評価器で共有する。`scaled` の制約を実際に必要な能力へ限定する。新たな公開係数 trait や依存の導入は前提としない。

- 除算・剰余・比較などを持たない係数型で `scaled` を実行し、実部・虚部の計算結果を検証する。
- 単精度・倍精度、項順序・重複・零係数、および非 Clone な operand を扱う既存の契約を維持する。
- 所有値の係数・operand の移動と、空・単一項のコンテナ割り当て特性を維持する。

このメモのコンパイル失敗は指摘を再現するための結果であり、既存の workspace テストの失敗ではない。

### 制約の見直し結果

`qmb-core`・`qmb-spin-half`・`qmb-basic` の公開型・メソッド・trait 実装と評価の補助処理を確認した。構造を定義するための `LocalStructure` と、値を照合するための `Eq` は数値演算の制約と区別する。メソッド固有の数値制約はその `where` 節に置き、trait 実装の成立条件は対応する能力の実装に限定する。

| 対象 | 修正内容 |
| --- | --- |
| `LinearCombination::scaled` | `Num` を外し、メソッドに `Clone + Add + Sub + Mul` だけを要求する。`primitive` の `Zero + One` もメソッドごとの制約とする |
| 複素係数の演算 | [coefficient.rs](../crates/qmb-core/src/coefficient.rs) に必要な能力だけを要求する共通処理を置き、線型結合・局所評価・複合評価から使う |
| 基底 | 展開・順序番号・列挙を単一の `Basis<P, T>` へ統合する。共通 trait に数値制約を置かず、各具体基底の実装に必要な制約を限定する |
| 評価後の内積 | 局所状態の評価後の内積処理を分離し、複合縮約には `L::State: InnerProduct<T>` だけを要求する。不要な `Act`・`Adjoint` を外す |
| 演算子の項走査 | `OpTerms` は零を生成しないため、`Zero` を外し、実際に使用する `Add` を要求する |
| 複合内積・期待値・trace・Hilbert–Schmidt 内積 | `One` の supertrait に含まれる `Mul<Output = T>` の重複指定を削除する。乗算能力自体は引き続き必要である |

未評価の式を受け付ける公開の内積・期待値は、作用・随伴の節点を処理するため `Act`・`Adjoint` を引き続き要求する。演算子の trace も積・随伴・恒等演算子を処理するための能力を維持する。特定の入力値にその節点がないことだけを理由に、必要な制約を外さない。

空間の照合・重複検出の `Eq`、借用した係数を所有して保持する際の `Clone`、spin の具体的な規則で定数・分数・符号を作るための制約は必要であることを確認し、維持した。保持・構築・`map` には追加の数値制約を設けていない。

基底は `expand`・`index`・`elements` を一つの `Basis<P, T>` 実装で提供する。各具体基底の実装に課した制約は、列挙・順序取得にも適用される。実装を簡潔にするため、独立した展開用 trait は設けない。spin-half・独立した三次元代数・テスト・doc test と、関連する設計文書をこの契約に統一した。

回帰検証では、`scaled` 用の係数型から除算・剰余・比較・零・単位元を除去して計算結果を確認した。さらに、数値 trait のない係数型を使う独自基底の展開・情報取得、最小限の係数能力を使う spin 基底の列挙、作用・随伴能力のない primitive の評価後の内積、`Zero`・`One` のない係数型での項走査を確認した。

`cargo test --workspace` の全77テスト（doc test を含む）、format check、Clippy、警告をエラーとするドキュメント生成が成功した。MSRV と `std` のない target 向けビルドは未検証である。

## 3. 演算子構文の重複

### 確認結果

対象は [operators.rs](../crates/qmb-core/src/expr/operators.rs) の `binary`・`scalar` と、[composite_operators.rs](../crates/qmb-core/src/expr/composite_operators.rs) の同名 macro。

局所式と複合式で、二項演算の所有値・借用値4通り、単項負号、複素係数による左右の乗算をほぼ同じコードで定義している。主な差は型引数 `I` の有無、必要な `Eq` 制約、二項演算の返却型が直接の式か `Result` かという点である。

動作不良は確認していない。演算子構文の追加・修正時に同じロジックを二重に保守する必要があるため、共通化の候補とする。

### 整理候補と検証条件

型引数・制約・返却型・構築処理を受け取る内部 macro への集約を検討する。公開の式 trait や evaluator の統合は、この重複解消のための必須条件としない。共通化により可読性や制約の把握が悪化する場合は、小さな共通部分に限定する。

- 局所式の infallible な API と複合式の fallible な API を維持する。
- 所有ハンドルは移動し、借用ハンドルだけを複製する。
- 所有値・借用値の全組み合わせ、左右の係数乗算、最小限の数値制約を既存テストで確認する。

## 4. 複合作用の構築処理の重複

### 確認結果

対象は [composite.rs](../crates/qmb-core/src/expr/composite.rs) の `State::act_selected` と `State::into_act`（記録時307行・324行付近）。

両メソッドで、演算子からの空間選択、状態空間との互換性検証、選択した空間の保持、`StateNode::Act` の構築を重複実装している。差は明示空間の指定の有無と、operand を複製するか移動するかである。

現在のエラー判定や空間選択に不一致は確認していない。将来、片方だけに検証や空間保持の変更が入ることを避けるための整理候補とする。

### 整理候補と検証条件

所有値の状態・演算子と任意の明示空間を受け取る内部処理への集約を検討する。借用 API はハンドルを複製して委譲し、所有値を使う演算子構文は移動して委譲する。

- 明示空間、既存の束縛、状態空間という優先順位を維持する。
- 参照 Index の不存在と空間不整合の検出、および状態空間を暗黙に拡張しない契約を維持する。
- 元の束縛と入力の不変性、選択空間の保持、共有と所有値・借用値の演算子構文を既存テストで確認する。
- 構築時に局所規則を呼ばず、数値型や primitive に追加の制約を課さない。

## 5. 抽象と具象の境界

### 確認結果

- [qmb-core](../crates/qmb-core/src/lib.rs) は共通の契約・式木・空間・評価を持ち、spin 固有の規則や UUID の表現・発行を通常依存に含めていない。
- [LocalStructure](../crates/qmb-core/src/local_structure.rs) は primitive の関連付けと固定次元を定め、恒等元や各演算能力は別の trait に分離されている。
- 空間・複合式の Index はジェネリックであり、照合が必要な処理だけが `Eq` を要求する。
- [qmb-spin-half](../crates/qmb-spin-half/src/lib.rs) は具体的な primitive・局所規則・基底を実装し、[qmb-basic](../crates/qmb-basic/src/lib.rs) は UUID の具体型・発行を担当する。
- [独立した三次元局所代数のテスト](../crates/qmb-core/tests/local_algebra.rs)により、core の公開 API だけを使った別の代数の局所・複合評価が検証されている。

レビューでは、この具象分離に不具合は見当たらなかった。

### crate 境界に関する確認事項

現在の[実装計画](implementation-plan.md)は、共通の式木・空間・評価を `qmb-core` に集約し、内部の責任を module で分離する方針である。`qmb-algebra` は設けていない。実装はこの現行文書に沿っている。

一方、以前の「core は trait と最小限の共通型に限定し、共通の代数処理を `qmb-algebra` へ分離する」という境界にはなっていない。これは現行設計との差分の確認事項であり、具体的代数への依存混入とは別の論点である。このメモによって分割変更を決定しない。

今後 crate 境界を再検討する場合は、公開契約・薄い有限線型結合・共有する構文パーツの所属を整理し、抽象契約から共通 evaluator への逆依存を作らないことを確認する。
