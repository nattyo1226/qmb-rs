# qmb-rs アーキテクチャ概要

更新日: 2026-10-17

## 1. 文書の位置づけ

本書は、[要件](requirements.md)に基づく設計の概要と、合意済みの設計判断を記録する。各対象の詳細な契約は `docs/design/` 以下の文書に記録する。具体的な Rust の型、公開 API、および内部実装は、対応する設計を決めた時点で追記する。

## 2. 責任分離

| 対象 | 担当すること |
| --- | --- |
| 局所構造 | 局所空間の情報、代数・表現、primitive と数学的能力の関連付け・整合性 |
| 状態・演算子 primitive | 局所的な内積・積・作用・随伴・trace、および対応する場合の parity |
| Index | 局所構造から独立した因子の識別子の発行と同一性 |
| 自由度・Hilbert 空間 | Index と局所構造の組、Factor・Tensor の再帰構造、構成要素・Index の列挙、因子順序、積の種類、grouping・互換性・部分系判定、複合系の数学的能力の合成と整合性 |
| 状態式・演算子式 | core の共通構文、線型性・共役線型性による拡張、不変な部分構造の共有 |
| 埋め込み・評価 | 局所式の配置と作用空間の確定、局所契約を保存する合成則、整合性検証、grading、必要な部分の評価 |
| 基底・export | 局所基底と tensor product 基底、通常の式木への展開・再展開、順序・列挙・要素数の導出、座標取得、写像の表現行列、外部の数値表現への変換 |
| 幾何・モデル構築 | Site の同一性・順序・関係、空間・Index・内部ラベルの配置、配置用 Index の発行補助、状態や Hamiltonian の構築 |

代数 core は幾何構造を必須とせず、自由度と式を直接構築できる。完全な密・疎行列を生成せずに代数オブジェクトを構築・合成・評価し、必要に応じて数値 backend に export する。

## 3. Index・自由度・局所構造・空間

Index は識別子のみを表し、局所構造や次元を持たない。局所構造は、局所 Hilbert 空間と、その上で実現される代数・表現を定める。自由度（Dof）は Index と局所構造の組とし、同じ局所構造を持つ複数の因子を Index で区別する。

局所状態・演算子に Index を付与することで、所属先・作用先の因子を識別する。元の局所構造は局所状態・演算子が保持する。この付与は、spectator を含む全 Hilbert 空間への束縛とは別の操作である。

局所構造が保持する情報と数学的能力の整合性は、[局所構造の設計](design/local-structure.md)に定める。局所構造は、同じ定義・定義パラメータを持つ場合に一致とする。別々に構築・復元した場合もこの条件を用い、数学的同型の判定や primitive の自動対応付けは導入しない。詳細は[局所構造の一致条件](design/local-structure.md#4-局所構造の一致条件)に定める。定義の識別方式などの実装設計は未決とする。

Hilbert 空間自体を、基本自由度の Index と局所構造を持つ Factor、および ordinary / graded の種類と順序付きの子 Hilbert 空間を持つ Tensor の再帰構造として表す。Tensor の子に Tensor を含められる。Factor と Tensor は概念上の名前とする。基本因子の順序は子を左からたどった葉の Index 列で表し、Index の値の大小から決めない。基底は空間とは別に選ぶ。

Grouping は空間の木の括り方で表し、そのための独立した Group 型は追加しない。配置層が site と部分空間、内部ラベルと基本因子の対応を管理する。局所複合代数の数学的能力は、子の局所規則と共通の合成・評価機構から処理する。

空間の互換性は、基本因子の Index・順序・局所構造と、空・単因子 tensor product の同一視および同種の積の結合則を適用した後の tensor 構造に基づく。保持する木構造と数学的な互換性を分け、括り方だけの違いでは互換性を変えない。構築時の平坦化は要求せず、不変な子空間を共有できるようにする。

部分系判定は、基本因子の Index の包含、対応する局所構造の一致、相対順序の保存、および積の種類の整合性に基づく。木の部分木や連続した因子列であることは要求しない。任意の因子集合を指定した部分系の取得と Regrouping の操作は提供しない。Tensor の直下の子空間と、全葉の Index は順序を保って列挙できるようにし、既存の構成を読み取れるものとする。詳細は [Hilbert 空間の再帰構造](design/hilbert-space.md)に定める。残る内部実装上の選択は、具体的な保持形式・所有権と共有方式・判定の走査と比較手順である。

## 4. Index の契約

Index は局所構造を指定せずに独立に発行し、自由度はあらかじめ発行した Index と局所構造から構築する。局所状態・演算子には発行済みの Index を明示的に付与する。自由度の構築や局所式への付与で Index を自動発行する経路は設けない。

Index は UUID のような衝突確率が十分低い生成方式を用いて発行し、同一ランタイム内および複数ランタイム間で、独立に発行した Index の一意性を仮定する。Index と局所構造の対応を全体で登録・固定する機構は設けず、合成・埋め込み・評価に必要な整合性は、その操作の対象から検証する。

詳細は [Index の契約](design/index.md)に定める。Index の具体的な生成方式・バージョン、および Rust の型・API は未決とする。

保存・復元と複数ランタイムの契約は、[既存テンソルネットワークライブラリの脚の管理方式](design/tensor-leg-identity-survey.md)の調査を参考に、以下のとおり採用する。詳細は [Index の契約の 7 節](design/index.md#7-保存復元と複数ランタイム)に定める。

| 操作 | 契約 |
| --- | --- |
| 保存した対象の復元 | 元の Index を保持し、同じ自由度の記述を復元する。共有所有や同一のメモリ上のオブジェクトへの復元は要求しない |
| 保存した対象から独立した系の作成 | 新しい Index を発行し、空間・状態・演算子の参照を一貫して付け直す |
| 複数ランタイムからの持ち寄り | Index で因子を照合し、局所構造と空間の互換性を検証する |

保存形式と具体的な公開 API は未決とする。これらの契約は、保存機能や並列評価を初期版の必須実装に追加するものではない。

## 5. Primitive・式木の数学的能力

状態 primitive は内積、演算子 primitive は Product・ActOn・随伴・trace を提供する。Product・ActOn・随伴は、同じ局所構造の primitive の有限線型結合を返す。局所構造はこれらの能力を関連付け、次元、所属、表現パラメータ、恒等演算子と、結合則・作用・内積・随伴などの整合性を定める。

Core の共通の式木は、加算・scalar multiplication・zero と、積・作用・随伴などの構築を提供する。必要な評価時に線型性・半双線型性・共役線型性を用いて primitive の規則へ委譲し、構築時には式全体を展開しない。Norm、bra、期待値、commutator、Hilbert–Schmidt 内積などは共通機構から導出する。

Primitive の線型独立性は要求せず、source の構造比較と数学的な等価性を区別する。指定基底への座標取得は別の接続として扱う。詳細は [局所 primitive・式木の数学的能力](design/primitive-expression.md)に定める。具体的な Rust の型・trait シグネチャ・式木の内部表現は未決とする。

## 6. 基底の数学的能力

基底の定義を表す `PauliBasis` のような struct が `Basis<Primitive>` を実装し、primitive の基底展開、基底要素の順序番号の取得、および順序付きの遅延列挙を提供する。局所基底要素は primitive の部分集合とし、対象空間全体に線型独立かつ完全であることを要求する。

基底要素数は、対応する局所構造と対象種別から導出する。局所 Hilbert 空間の次元が `d` なら状態基底は `d`、全演算子基底は `d²` 要素となる。Basis に独立した要素数の提供を要求しない。

Core の共通機構が展開を線型に式全体へ拡張し、順序番号から座標を得る。内積・Gram 行列・双対基底は展開の実装に利用できるが、Basis の必須の独立能力とはしない。詳細は [基底の数学的能力](design/basis.md)に定める。具体的な Rust の API・保持形式・共有方式は未決とする。

初期版で利用者が明示的に式を整理する操作は、指定基底への展開と係数取得に限定する。分配だけ、局所積だけなど、特定の簡約ルールのみを選択して適用する独立した操作は future work とする。必要な分配・局所積・係数の結合は、基底展開や作用・内積・trace の内部処理として維持する。元の source を保持し、通常の評価に基底展開を必須としない。

複合基底は基本因子ごとの局所基底の tensor product に限定し、Hilbert 空間の因子順序と既存の mixed-radix に従う。Grouping は基底を変えない。展開結果は通常の式木とし、基底識別情報や展開済み状態を保持させない。別基底への変更は再展開で扱い、Index・局所構造・確定した空間を保持する。数値座標を export する場合は、その基底・順序などの解釈を別途確定する。

再利用可能な係数データは、写像の入力・出力基底に対する表現行列として整理する。各入力の線型性／共役線型性を明示し、複数入力の係数列を指定順序で tensor product にまとめて行列を適用する。基底の列挙・通常の演算・出力基底への展開と係数取得から構成する共通操作とし、専用 trait の実装は要求しない。数式・共役指定・非正規直交基底・検証対象の詳細は [写像の表現行列](design/representation-matrix.md)に定める。

## 7. 埋め込み・複合空間の数学的能力

局所演算子式と Index の組を複合演算子式の葉とし、和・積などで合成する。状態側も局所状態式と Index の組から tensor product と線型結合で構成する。Index の付与を配置、spectator を含む全作用空間の確定を束縛と呼び分ける。埋め込みは局所式の線型結合・積・随伴・恒等演算子を保存する。状態に新しい因子を追加する場合は、その状態または明示的な埋め込み写像を必要とする。

複合 Hilbert 空間が、局所構造に相当する整合性の責任を持つ。子の構造・因子順序・ordinary / graded の種類から積・作用・内積・随伴・trace などを合成し、共通の合成・埋め込み・評価機構がその契約を実現する。独立した複合構造型は要求しない。

同じ合成則を入れ子にも適用し、同種の積の括り方と空・単因子の同一視に対して数学的結果を一致させる。Graded では積・作用・tensor の随伴に符号規則を適用し、通常の正定値な内積と非正規化 trace を維持する。Partial trace は埋め込み後の通常の作用を縮約し、残存空間を保持する。

局所契約を満たすことは局所構造の提供者、契約を保存する合成則は共通機構の責任とする。操作時には適用の前提を検証し、数学的法則を任意の実装について実行時に自動証明することは要求しない。能力一覧・数式・検証対象の詳細は [埋め込み・複合空間の式と数学的能力](design/composite-expression.md)に定める。具体的な API・内部表現・評価手順と個別機能の実装範囲は別途決める。

## 8. Geometry・Site と自由度の配置

Site に Factor または Tensor を対応付け、その空間の全葉の Index をそのまま Site に所属させる。一つの配置では、各 Index をちょうど一つの Site に割り当て、Site 間の重複・未配置・必要数の過不足を拒否する。自由度数 `0` の Site と空の Geometry は認める。

既存空間から構成要素・Index の列挙によって配置する経路と、Geometry が Site ごとの自由度数から Index 列を先に発行し、それを用いて局所構造・Hilbert 空間を構成する経路を提供する。各 Geometry が入力順序・Site 内順序・必要数に関する既定の配置規則を定め、配置で既存の tensor ordering を暗黙に変更しない。Geometry は局所代数の種類を決めない。

Site の同一性は所属 Geometry とその中の識別子の組とし、複製・共有では保持する。順序番号に加えて任意の内部ラベルを扱い、同じ Site 内でラベルが異なる Index を指す重複を拒否する。近接関係からは、配置情報を通じて両 Site の順序付き Index 列の組を得る。相互作用項の選択はモデル構築側が担当する。

Geometry と確定した配置は構築後に不変とし、別の幾何や配置は新しく構築する。同じ Index を別の配置で利用してよく、Index と Site の対応を全体で固定しない。詳細は [Geometry・Site と自由度の配置](design/geometry.md)に定める。具体的な識別方式・API・保持形式と各 Geometry の個別規則は別途決める。
