# qmb-rs アーキテクチャ概要

更新日: 2026-10-14

## 1. 文書の位置づけ

本書は、[要件](requirements.md)に基づく設計の概要と、合意済みの設計判断を記録する。各対象の詳細な契約は `docs/design/` 以下の文書に記録する。具体的な Rust の型、公開 API、および内部実装は、対応する設計を決めた時点で追記する。

## 2. 責任分離

| 対象 | 担当すること |
| --- | --- |
| 局所構造 | 局所空間の情報、代数・表現、primitive と数学的能力の関連付け・整合性 |
| 状態・演算子 primitive | 局所的な内積・積・作用・随伴・trace、および対応する場合の parity |
| Index | 局所構造から独立した因子の識別子の発行と同一性 |
| 自由度・Hilbert 空間 | Index と局所構造の組、因子順序、tensor product の種類、内部因子と grouping の対応 |
| 状態式・演算子式 | core の共通構文、線型性・共役線型性による拡張、不変な部分構造の共有 |
| 埋め込み・評価 | 作用空間の確定、整合性検証、grading、必要な部分の評価 |
| 基底・export | 座標取得、係数データ、外部の数値表現への変換 |
| 幾何・モデル構築 | site と関係、自由度の配置、状態や Hamiltonian の構築 |

代数 core は幾何構造を必須とせず、自由度と式を直接構築できる。完全な密・疎行列を生成せずに代数オブジェクトを構築・合成・評価し、必要に応じて数値 backend に export する。

## 3. Index・自由度・局所構造・空間

Index は識別子のみを表し、局所構造や次元を持たない。局所構造は、局所 Hilbert 空間と、その上で実現される代数・表現を定める。自由度（Dof）は Index と局所構造の組とし、同じ局所構造を持つ複数の因子を Index で区別する。

局所状態・演算子に Index を付与することで、所属先・作用先の因子を識別する。元の局所構造は局所状態・演算子が保持する。この付与は、spectator を含む全 Hilbert 空間への束縛とは別の操作である。

局所構造が保持する情報と数学的能力の整合性は、[局所構造の設計](design/local-structure.md)に定める。局所構造は、同じ定義・定義パラメータを持つ場合に一致とする。別々に構築・復元した場合もこの条件を用い、数学的同型の判定や primitive の自動対応付けは導入しない。詳細は[局所構造の一致条件](design/local-structure.md#4-局所構造の一致条件)に定める。定義の識別方式などの実装設計は未決とする。

初期版の空間は、基本因子の Index と局所構造、および ordinary または graded の tensor product の種類を中心に表す。因子順序は Index の順序付き列で指定し、Index の値の大小から決めない。局所複合構造を扱う場合は、展開した基本因子と site・grouping の対応を保持する。基底は空間とは別に選ぶ。

空間の互換性は、基本因子の Index・順序・局所構造と、空・単因子 tensor product の同一視および同種の積の結合則を適用した後の tensor 構造に基づく。grouping の表示の違いだけでは互換性を変えない。具体的な保持形式と比較手順は今後設計する。

## 4. Index の契約

Index は局所構造を指定せずに独立に発行し、自由度はあらかじめ発行した Index と局所構造から構築する。局所状態・演算子には発行済みの Index を明示的に付与する。自由度の構築や局所式への付与で Index を自動発行する経路は設けない。

Index は UUID のような衝突確率が十分低い生成方式を用いて発行し、同一ランタイム内および複数ランタイム間で、独立に発行した Index の一意性を仮定する。Index と局所構造の対応を全体で登録・固定する機構は設けず、合成・埋め込み・評価に必要な整合性は、その操作の対象から検証する。

詳細は [Index の契約](design/index.md)に定める。Index の具体的な生成方式・バージョン、および Rust の型・API は未決とする。

保存・復元と複数ランタイムの契約は、[既存テンソルネットワークライブラリの脚の管理方式](design/tensor-leg-identity-survey.md)の調査を参考に、以下のとおり採用する。詳細は [Index の契約の 7 節](design/index.md#7-保存復元と複数ランタイム)に定める。

| 操作 | 契約 |
| --- | --- |
| 保存した対象の復元 | 元の Index を保持し、同じ自由度の記述を復元する。共有所有や同一のメモリ上のオブジェクトへの復元は要求しない |
| 保存した対象から独立した系の作成 | 新しい Index を発行し、空間・状態・演算子の参照を一貫して付け直す |
| 複数ランタイムからの持ち寄り | Index で因子を照合し、局所構造と空間の互換性を検証する |

保存形式と具体的な公開 API は未決とする。これらの契約は、保存機能や並列評価を初期版の必須実装に追加するものではない。

## 5. Primitive・式木の数学的能力

状態 primitive は内積、演算子 primitive は Product・ActOn・随伴・trace を提供する。Product・ActOn・随伴は、同じ局所構造の primitive の有限線型結合を返す。局所構造はこれらの能力を関連付け、次元、所属、表現パラメータ、恒等演算子と、結合則・作用・内積・随伴などの整合性を定める。

Core の共通の式木は、加算・scalar multiplication・zero と、積・作用・随伴などの構築を提供する。必要な評価時に線型性・半双線型性・共役線型性を用いて primitive の規則へ委譲し、構築時には式全体を展開しない。Norm、bra、期待値、commutator、Hilbert–Schmidt 内積などは共通機構から導出する。

Primitive の線型独立性は要求せず、source の構造比較と数学的な等価性を区別する。指定基底への座標取得は別の接続として扱う。詳細は [局所 primitive・式木の数学的能力](design/primitive-expression.md)に定める。具体的な Rust の型・trait シグネチャ・式木の内部表現は未決とする。
