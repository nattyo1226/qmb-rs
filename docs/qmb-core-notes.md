# qmb-core 共通式・評価の実装検討メモ

更新日: 2026-10-22

## 1. 位置付けと提供範囲

本書は、[実装計画](implementation-plan.md)の Step 2「局所式と評価」に向けた一時的な作業用記録である。恒久的な仕様書として維持することは想定せず、既存の恒久ドキュメントからはリンクしない。ここに記す API や機能が実装済みであることは意味しない。

局所式の数学的契約は、[局所 primitive・式木の数学的能力](design/primitive-expression.md)と[要件](requirements.md)に従う。共通の代数処理は `qmb-core` に集約し、局所式・評価に加え、後続の Index・空間・複合式・基底処理も core に置く。具体的代数・Geometry・数値 export はそれぞれの crate に分離する。

crate の責任、公開する式型、`Arc` による共有、作用の `act` と評価の `evaluate` の役割は確定事項とする。有限線型結合・式木・局所規則の返却形式の接続は一体で再設計する。未決事項と後続段階の設計事項は第6節にまとめる。

局所状態・演算子の構築、加算、係数乗算、zero・identity、演算子積、作用、内積、随伴、局所 trace を実装する。これらから作れる commutator・anticommutator、局所期待値、Hilbert–Schmidt 内積も含める。

norm・正規化・bra は、実数値の扱いと API を別途検討してから追加する。Index・空間・配置は Step 3、基底展開・座標取得は Step 5 に置く。これは初期版全体からそれらの機能を除外するものではない。

`qmb-core` の `no_std + alloc` を維持する。`Arc`・`Vec` など既存の標準機構で実装し、Step 2 では新しい production 依存や feature は追加しない。

core 内を局所契約・有限線型結合、式・構築構文、空間、評価、基底処理に分け、主要な公開型を crate root から再公開する。Step 2 では局所式と評価に必要な部分を追加し、具体的代数は検証に利用する。通常依存へ具体的代数・Geometry・数値 backend を持ち込まない。

source の自動保持、式の構造比較、`Debug`・`Display` を含む式表示は後続へ延期する。現在の式と source を別々に保持する二重のルートや、それらの参照・比較 API は導入しない。操作は入力を変更せず、利用者は必要なら評価前の式を変数に保持できる。不変実体の共有は維持する。

### 1.1. 実装前の前提作業：状態 primitive の Act の整備（完了）

Step 2 の前提作業として、`qmb-core` の作用 API を以下の状態 primitive 側の `Act<O, T>` の契約に揃えた。この整備は 2026-10-21 に完了した。共通式木・評価は未実装である。以下は現在実装済みのシグネチャであり、返却形式は第2.3節の再設計対象に含める。

`Act` は「この状態 primitive に、指定した演算子 primitive を作用させられる」能力を表す。

```rust
pub trait Act<O, T>: Sized {
    /// 数学的には operator * self を計算する。
    fn act(&self, operator: &O) -> LinearCombination<Self, T>;
}
```

`LocalStructure<T>` の関連型の制約は次の形とした。`DIMENSION` と `identity()` の契約は維持している。

```rust
type State: InnerProduct<T> + Act<Self::Operator, T>;
type Operator: Product<T> + Adjoint<T> + Trace<T>;
```

以下の前提作業を完了した。

1. core の trait 定義・再公開・関連型の制約を変更した。
2. spin の作用規則を `Act<SpinHalfOperator, T> for SpinHalfState` として実装し、局所規則の数値制約と数学的結果を維持した。
3. 三次元局所代数などのテスト実装、呼び出し箇所、doc test、作用の実装先を説明する既存ドキュメントを契約に揃えた。
4. 既存の direnv 環境（Rust 1.98.0）で、局所規則・型制約を含む workspace の全26テスト（doc test 含む）、format check、Clippy、警告をエラーとするドキュメント生成の成功を確認した。

Act は状態をメソッドの受け手とし、数学的には演算子の左作用を計算する。primitive の `Act::act` は局所規則を計算して有限線型結合を返す。一方、状態式の `act` は遅延した作用を構築し、`evaluate` が必要な primitive の `Act::act` を呼ぶ。両者の役割を区別する。

## 2. 式の型・内部表現・共有

### 2.1. 公開する式型

`LocalState<L, T>` と `LocalOperator<L, T>` の二型を採用する。`L: LocalStructure<T>` から primitive 型を取得し、局所構造と係数精度の整合性を型で保証する。

将来の複合状態・演算子とは公開型を分ける。共通式木を使う契約は、局所式と複合式の公開型を一つに統一することまでは要求しない。

### 2.2. Arc による所有権と不変共有

式節点・primitive は `Arc` を基本として、不変な実体を共有する。式の `Clone` は共有参照の複製だけにし、primitive や `T` の `Clone` を要求しない。評価中は借用を優先し、不要な `Arc::clone` を避ける。

primitive に一律の `Clone`・`Copy`・`Send`・`Sync`・`'static` を要求しない。借用を含む primitive も、その型の lifetime の範囲で利用できるようにする。係数は節点内に保持し、数値演算の制約は必要な操作に付ける。

`Send + Sync` は保持する型に応じて成立させる。非 `Send` な primitive も格納でき、その場合は式のスレッド間共有ができない。将来のスレッド間共有への接続を重視して `Arc` を採用するが、並列 evaluator の実装は後続へ延期する。

共有の内部表現は非公開とし、`Rc`／`Arc` 切替 feature は設けない。`Arc` は参照の複製・破棄に atomic 操作を用いるため、`Rc` より参照カウントのコストがある。借用による読み取りのたびに参照カウントを操作する必要はない。

`alloc::sync::Arc` は `no_std + alloc` で利用できるが、ポインタ幅の atomic 操作を持つ target が必要となる。これらの制約は既存環境の Rust 1.98.0 の `alloc` 実装で確認した。性能比較は未実施である。

### 2.3. 線型結合と式木の接続

有限線型結合、局所規則の結果、遅延式を core 内で一体として設計する。既存の `LinearCombination` を活用し、同じ線型構造を表す型を独立に重ねない。具体的代数も core の共通型を直接利用でき、代数ごとの式木を作らない。

crate の統合だけで要素型変換や詰め替えが消えるとはみなさない。`LinearCombination` の要素型、式節点との関係、primitive が返す値と共有済みの値の扱いをまとめて決める。式とは別の汎用出力 trait を追加して接続する方式は採用しない。

必要な数学的構成は次のとおりとする。内部の enum variant 一覧や保持形式を確定する表ではない。

| 対象 | 必要な構成 |
| --- | --- |
| 状態式 | primitive、zero、和、係数乗算、演算子の作用を表す `Act` 節点 |
| 演算子式 | primitive、zero、identity、和、係数乗算、積、随伴 |

内積・trace は scalar を求める操作とし、今回は scalar 用の式木を導入しない。

和や係数乗算を二分の `Add`・`Scale` 節点で表すか、有限線型結合に統合するか、また積をどう保持するかは未決とする。有限線型結合を取り込む際に各項を別の節点列へ変換する方式や、評価用の要素型を別に設ける方式も確定しない。構築時の未評価、入力順序の保存、変更されない大きな部分構造の共有は維持する。

### 2.4. 複合式への接続

初期版では、一つの系に含まれる全基本因子を同じ局所構造型 `L` に揃える。Step 3 でも型付き局所式を共有して保持し、同じ `L` の局所式と Index を組にして複合式の葉とする。複合式の葉から必要な操作を局所 evaluator へ静的に委譲する。

異種局所構造の混在・合成と、そのための型消去 API・保持機構は後続へ延期し、Step 2・3 の設計対象に含めない。独自代数は `L` の別実装として別の系で単独利用できる。同種因子の入れ子や一つの Site への複数自由度の配置は維持する。

将来の異種構造への対応や、型消去後の `Send + Sync` の扱いは、その機能を導入する段階で設計する。初期版のために `'static` 等の追加制約を先に課さない。

## 3. 公開 API と構築規約

### 3.1. メソッドと演算子構文

名前付き constructor・メソッドを基本 API とし、演算子構文は同じ処理への入口とする。primitive・有限線型結合の取り込みは局所規則を実行せず、通常の式を構築する。有限線型結合の具体的な取り込み API は第2.3節と併せて決める。

primitive・有限線型結合の取り込みは所有値を受け取り、式同士の操作は `&self` と共有借用を基本とする。変更されない operand は `Arc` で共有する。名前付き API は inherent method とする。primitive の局所規則と式の遅延構築の役割を区別し、演算 trait の式型への実装の可否は返却形式と併せて決める。

以下の `P` は、状態式では `L::State`、演算子式では `L::Operator` を表す。型制約は第4.3節に従い、必要な操作ごとに付ける。

| 対象 | API・引数・返却値 |
| --- | --- |
| 両式型の primitive 取り込み | `primitive(p: P) -> Self` |
| 両式型の零・和 | `zero() -> Self`、`sum(iter: impl IntoIterator<Item = Self>) -> Self` |
| 両式型の係数乗算 | `scaled(&self, coefficient: Complex<T>) -> Self` |
| 演算子の恒等元・積・随伴 | `identity() -> Self`、`product(&self, rhs: &Self) -> Self`、`product_all(iter: impl IntoIterator<Item = Self>) -> Self`、`adjoint(&self) -> Self` |
| 状態式への遅延作用 | `act(&self, operator: &LocalOperator<L, T>) -> Self` |
| 状態式の評価 | `evaluate(&self) -> Self` |
| 状態式の内積 | `inner_product(&self, rhs: &Self) -> Complex<T>` |
| 演算子式の局所 trace | `trace(&self) -> Complex<T>` |
| 演算子式の導出操作 | `commutator(&self, rhs: &Self) -> Self`、`anticommutator(&self, rhs: &Self) -> Self`、`hilbert_schmidt_inner_product(&self, rhs: &Self) -> Complex<T>` |
| 状態式の局所期待値 | `expectation(&self, operator: &LocalOperator<L, T>) -> Complex<T>` |

`+`・`-`・単項 `-`、演算子積、演算子と状態の積、複素係数による左右の乗算を提供する。式同士は所有値・借用値の組み合わせに対応させる。実数係数はまず `Complex<T>` への明示変換を基本とし、暗黙の精度変換は導入しない。

### 3.2. constructor の意味

内部表現によらず、次の意味を満たす。

| 入力 | 意味 |
| --- | --- |
| 空の和・有限線型結合 | zero |
| 空の演算子積 | identity |
| 一要素の和・積 | その要素と同じ対象 |
| 複数要素の和・積 | 入力順を保つ和・積 |
| 有限線型結合 | 項の順序と係数を保つ式 |

構築に primitive や係数の比較を要求せず、係数 `0`・`1` による自動的な項の除去・結合を要求しない。保持する節点構造と有限線型結合の取り込み方法は第2.3節で決める。

## 4. 評価

### 4.1. 遅延構築と作用の評価

`product`・`act`・`adjoint` は遅延式を構築し、`inner_product`・`trace` は必要な処理を実行して `Complex<T>` を返す。`LocalState::act(&self, operator)` は `Act(operator, state)` 節点を含む状態式を構築し、その式に対する `LocalState::evaluate(&self) -> Self` が作用を評価する。

以下は利用形の例であり、実装・検証済みのコードではない。

```rust
let expr = state.act(&operator); // 遅延した作用を構築する
let result = expr.evaluate();    // 構築済みの状態式を評価する

let result = state.act(&b).act(&a).evaluate(); // B、A の順に作用させ、A(Bψ) を得る

let expr = &operator * &state; // 演算子構文も同じ遅延構築を行う
let result = expr.evaluate();
```

`act` と `evaluate` はともに共有借用を受け取り、元の式を変更せず通常の `LocalState<L, T>` を返す。加算・作用・内積を続けて適用でき、`act` のメソッドチェーンを構築するだけでは局所規則を呼ばない。内部の有限線型結合を専用の公開結果型にはしない。汎用の `simplify` や局所積だけを整理する公開操作は追加しない。

`evaluate()` は状態式の和・係数乗算・入れ子の作用をたどり、必要な primitive の `Act::act` に委譲し、作用後の状態式を得る。例えば `Act(Sx, Up)` は `Down` の係数 `1/2` の式になる。基底を入力に取らず、選択基底への展開・座標化や密・疎行列の生成も行わない。入力を変更せず、すでに作用が評価されている部分は共有して再利用する。内積・期待値は、利用者が事前に `evaluate()` を呼ぶことを必須とせず、必要な部分を内部で評価する。

### 4.2. 評価経路と結果の項

状態項の走査、演算子の作用、演算子項の走査を目的別に分ける。線型構文の分解と係数処理は内部で共用し、すべての評価を演算子の完全展開へ集約しない。

`(AB)ψ` は `B`、`A` の順に作用させ、不要な primitive 間の `Product` を呼ばずに処理する。一方、`trace(AB)` などで必要な局所積は `Product` に委譲する。随伴は構築時に分配せず、評価時に係数の共役と積順序の反転を処理する。

`evaluate()` の結果では、同じ primitive の項を自動結合せず、零係数の項も自動削除しない。明示した zero と、局所規則が返す空の有限線型結合は zero として処理する。和は左から右、演算子積の作用は右から左に処理し、局所規則が返す項の順序を保存する。評価に primitive の比較を必須とせず、数学的に零を表す式と明示した zero を区別する。zero の内部表現は第2.3節の設計で決める。同類項の結合は Step 5 の基底展開・座標取得で行う。

評価中の一時表現は第2.3節と一体で設計し、既存の葉や恒等作用など入力をそのまま利用できる経路では共有実体を再利用する。係数を変更するために primitive 本体を複製せず、数値係数の複製は各演算で必要な箇所に限定する。特定の一時表現をすべての評価経路に共通する完全展開形として強制しない。

### 4.3. 数値制約とエラー

型の保持と構築には最小限の制約を付ける。評価では `T: Clone + Num`、共役を使う操作には追加で `Neg<Output = T>` を要求する方針とし、実際の制約は各操作の必要条件を確認して付ける。`Float`・`Copy` は一律に要求しない。

局所構造と精度は型で一致し、primitive の規則も infallible なので、基本的な局所評価には包括的な `Result` を付けない。NaN・infinity を独自に拒否せず、内部の項除去にも近似許容誤差を使わない。

実数値を返す norm 等のエラー設計は、その機能を追加する段階で決める。

## 5. 完了条件と検証

spin と独立した三次元局所代数の双方で、それぞれの代数だけを使う別の系を構成し、積・作用・内積・随伴・trace を小規模行列と照合する。両代数を一つの系に混在させない。単精度・倍精度、虚部のある係数、線型従属な primitive、zero・identity・空和・空積を含める。

規則の呼び出し回数と primitive の複製回数を観測し、構築時の未評価、式の共有、入力の不変性、`(AB)ψ` で不要な `Product` が呼ばれないことを確認する。精度・局所構造の混在は compile-fail テストで検証する。

`ψ.act(&b).act(&a)` と `ψ.act(&a.product(&b))` の数学的な一致を確認し、`act` のチェーンが遅延構築、`evaluate` が評価であることと、左作用の順序を検証する。

評価結果を再合成・再評価でき、入力の式を保持した利用者が引き続きそれを計算に利用できることを確認する。基底を与えずに評価できること、constructor の空・一要素・複数要素の意味、係数 `0`・`1` の保持、評価結果の重複項・零係数の保持、評価済み部分の再利用も検証する。source の自動保持・構造比較・式表示は受入条件に含めない。

既存の direnv 環境で対象テスト、workspace の test・format check・Clippy・ドキュメント生成を確認する。これは今後の検証方針であり、Step 2 のチェックを実行済みとするものではない。

## 6. 未決事項と後続の設計

実装前に、線型結合と式木の接続を次の点から一体で設計する。それ以外の確定方針を、この再設計で未決に戻さない。

- `LinearCombination` と式節点の関係、和・係数乗算・積の保持形式。
- primitive の局所演算の返却形式、所有値と共有済みの値の接続、有限線型結合を取り込む API。
- 評価の内部走査と一時表現。既存の共通型を活用し、冗長な線型表現や反復的な詰め替えを避ける構成。

数値演算ごとの正確な trait 制約、演算子構文の所有値・借用値の実装、非公開フィールドや補助関数は、その設計に基づいて具体化する。後続段階では次を扱う。

- Step 3 で同じ局所構造型 `L` の局所式を配置・合成する具体的な型と API。
- norm・正規化・bra の詳細。

非公開の module 分割などは、確定方針とテスト条件の範囲内で実装時に判断する。異種局所構造の混在・合成と型消去、source の自動保持・式の構造比較・表示は初期版の対象外とする。
