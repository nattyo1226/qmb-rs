# 基底の数学的能力

更新日: 2026-10-27

## 1. 対象と合意した契約

本書は、[要件](../requirements.md)と[アーキテクチャ概要](../architecture.md)に基づき、状態・演算子の局所 primitive に対応する基底、その tensor product による複合基底、および式の展開に関する契約を定める。[局所 primitive・式木の数学的能力](primitive-expression.md)における基底との接続の詳細設計である。

基底の能力契約、式全体への展開、複合基底、座標取得は `qmb-core` が担当する。具体的代数の crate は局所基底と primitive の展開規則を実装する。得られた係数を外部数値コンテナへ格納する処理は `qmb-export` に置く。

基底の定義は `PauliBasis` のような struct が表し、対象の要素型を指定した `Basis<P, C>` を実装する。その実装が、特定の primitive たちを基底とする規則と、各 primitive をその基底へ展開する手続きを提供する。状態基底の展開は `LinearCombination<S, C>`、演算子基底の展開は `LinearCombination<O, C>` を返す。式木側が要素を `map` して通常の式へ取り込む。利用者が基底要素の配列や集合そのものを入力することは要求しない。

展開・順序番号・列挙は単一の `Basis<P, C>` 実装で提供する。共通 trait 自体には数値制約を置かず、各具体基底の実装に、その展開規則で必要な能力だけを要求する。この実装の制約は `index`・`elements` にも適用される。係数精度を推論できない情報取得では、`<B as Basis<P, C>>::elements` のように明示する。

既存の `LinearCombination` を返す契約と `Basis<P, C>` を維持し、[実装計画](../implementation-plan.md)の Step 2 で core・spin-half・テスト実装と局所式の接続を整備する。`StateBasis`・`OperatorBasis` は削除し、利用側で次の制約を直接指定する。両 marker trait の定義・再公開・実装宣言・テストや doc test の利用箇所も同じ Step 2 で移行し、互換用の marker trait や別名は残さない。式全体への展開、複合基底、座標取得の実装は Step 5 に置く。

| 基底を使う処理 | 型制約 |
| --- | --- |
| 局所状態の基底処理 | `B: Basis<S, C>` |
| 局所演算子の基底処理 | `B: Basis<O, C>` |

局所基底要素は対応する primitive の部分集合とし、線型独立かつ対象空間全体に完全であることを要求する。局所基底要素として一般の式を指定することは本契約に含めない。正規直交性は要求しない。Primitive 全体は線型従属でもよい。

基底を使う側は、対応する[局所構造](local-structure.md)、その定義パラメータ、および対象が状態か演算子かを確定する。型の対応は `Basis<S, C>` または `Basis<O, C>` で指定し、独立した所属宣言は要求しない。選択基底は局所構造や自由度の Index の同一性とは区別する。

初期版の複合基底は、同じ primitive 型 S・O の基本因子に対し、一つの局所基底を全因子へ共通に適用して構成する。因子ごとに異なる基底や定義パラメータを指定することは扱わない。2026-10-27に採用した実装方針は [Step 5 の一時設計メモ](../step-5-design.md)に記録する。異種局所構造を混在させた系の基底は後続へ延期する。別の独自代数の基底は、その代数だけを使う別の系で利用・検証する。

## 2. Basis の三つの能力

| 能力 | 入力 | 結果・契約 |
| --- | --- | --- |
| Primitive の基底展開 | 対応する対象空間の primitive | 選択された基底 primitive の有限線型結合 |
| 基底順序番号の取得 | primitive | 選択された基底要素である場合に、その順序番号を返す。基底要素でなければ番号は存在しない |
| 順序付きの列挙 | 基底の定義・パラメータ | 基底順序に従って、基底 primitive を必要に応じて列挙する |

基底を `B = {b_0, …, b_{n−1}}` とすると、任意の対応する primitive `p` について以下を与える。

```math
p=\sum_{\mu=0}^{n-1}c_\mu(p)b_\mu.
```

線型独立性によって、この展開の係数は一意となる。展開は対象全体を正確に表し、射影や成分の切り捨てを行わない。基底要素でない primitive も展開できるが、それ自体を指す基底順序番号は返さない。

| 展開する入力 | 返却型 |
| --- | --- |
| 状態 primitive `S` | `LinearCombination<S, C>` |
| 演算子 primitive `O` | `LinearCombination<O, C>` |

返却する線型結合の要素は選択した基底の primitive に限る。式木側は係数・項順序を保持した `map` と共通 constructor により、`Primitive`・`Scale`・`Sum` の通常の式へ取り込む。線型結合にも取り込み後の式にも基底情報や特別な展開済み状態は保持させない。取り込み後は通常の演算や別基底への再展開に使える。基底要素の条件と取り込みの整合性は検証対象とする。

順序番号は選択基底の中での zero-based な座標番号とし、primitive の表示名や値の大小から暗黙に決めない。自由度を識別する Index とは別の概念である。Step 2 では既存の `index(&self, primitive: &P) -> Option<usize>` を維持し、基底要素でなければ `None` を返す。

列挙は全要素の一括生成・保持を要求しない。Step 2 では既存の `elements(&self) -> impl Iterator<Item = P> + '_` を維持し、所有要素を遅延列挙する。順序番号から primitive を得る操作は列挙から導出でき、Basis の必須の独立能力にはしない。列挙の内部表現と基底 primitive の共有実体の管理方法は内部実装で定める。

## 3. 要素数の導出

基底要素数は、対応する局所構造と対象種別から共通機構で導出する。局所 Hilbert 空間の次元を `d` としたとき、以下の要素数になる。

| 対象 | 基底要素数 |
| --- | --- |
| 状態空間 | `d` |
| 全演算子空間 | `d²` |

Basis に独立した要素数の提供を要求しない。要素数を得る便利な操作を設ける場合も、上記の情報から導出する。primitive の個数や、列挙を完走して数えた値を要素数の定義にはしない。

この契約は対象空間全体に完全な基底を前提とする。部分空間基底・射影、および fermion の even 部分だけへの制限は初期版で扱わない。`state_basis_len<S>()`・`operator_basis_len<O>()` は対象 primitive の SpanDimension を参照して `Result<usize, DimensionOverflow>` を返す。O の span の次元は既に d² なので、この関数でさらに二乗しない。整数化できない次元のエラーは取得時に返し、基底や式の保持・構築には次元の能力を要求しない。

## 4. 能力間の整合性

- 列挙は基底要素を一度ずつ返し、第 `k` 要素の基底順序番号は `k` とする。
- 列挙順序と順序番号は、同じ基底定義・パラメータのもとで一致する。
- 列挙される要素数は、局所構造と対象種別から導出した数と一致する。
- 基底要素自身の展開は、係数 `1` のその要素となる。
- 任意の primitive の展開結果に現れる primitive は、選択された基底要素に限る。
- Primitive 間の線型関係を保存し、同じ数学的対象を表す式から同じ基底座標を得る。

これらと基底の線型独立性・完全性は、基底実装が満たす数学的な契約と検証対象である。全 primitive の列挙や、任意の実装に対する実行時の自動証明は要求しない。数値精度・特殊値・近似比較は既存要件に従う。

## 5. 式・座標取得・数値変換との責任分担

Basis は primitive 一つに対する展開を提供し、core の共通機構が線型性を用いて式全体へ拡張する。積・作用などを含む場合は、必要な局所規則と合成則を評価して基底へ展開する。展開された基底 primitive の順序番号を使って係数を座標へ対応付け、同じ基底要素の係数をまとめる。

`qmb-core` は、局所規則による `evaluate` とは別に、指定基底への展開と係数取得を提供する。基底に対する座標は数学的に一意であり、一般的な簡約の到達形や最適性を別途要求しない。入力の式は変更しない。

`expand_in` は基底展開の結果を既存の通常の式型で返す。数値表現への export に向けた集約済み座標は、対象式と基底を入力とする別の公開 API で取得する。座標取得に事前の `expand_in` 呼び出しや展開済み専用型を要求せず、展開結果へ座標コンテナ・基底情報・展開済みマーカーを付随させない。単一成分取得と未集約の寄与の列挙は今回の独立した公開 API の必須項目にしない。座標番号と返却形式の詳細は [Step 5 の一時設計メモ](../step-5-design.md)で具体化する。

内積、Gram 行列、および双対基底は、展開手続きを実装するために利用できるが、Basis が提供する必須の独立能力とはしない。直接の展開規則を提供できれば座標を取得できる。演算子内積を使う場合は、既存要件の非正規化 Hilbert–Schmidt 内積 `Tr(A†B)` に従う。

基底展開による式の整理・座標取得は、通常の積・作用・内積・trace の評価経路から分離し、これらの評価に選択基底を必須としない。式の整理や数値変換などで指定基底への展開を要求した時点で必要な部分を展開し、完全な密・疎行列を中間表現として要求しない。式の構造比較は初期版に要求せず、同じ基底要素の係数は基底の順序番号に基づいてまとめる。

分配だけ、局所積だけ、同類項の結合だけなどの個別の簡約ルール適用は、要件の 9.2 節に従って future work とする。これらの処理を、基底展開や作用・内積・trace などに必要な内部処理として用いることは維持する。係数の zero 判定・数値精度・許容誤差は既存要件に従い、近似比較の許容誤差で成分を黙って捨てない。

### 5.1. Tensor product による複合基底

複合基底は、一つの局所基底を全基本因子へ共通に適用し、Hilbert 空間の因子順序で tensor product にしたものに限定する。状態には局所状態基底、演算子には局所演算子基底を用い、指定された局所基底と対象空間から core が複合基底を導出する。利用者に別の複合基底オブジェクトの構築を要求しない。複数の因子をまとめて独自の基底を指定することや、もつれた基底を別に定義することは本契約に含めない。局所基底が完全なので、この制限によって表現できる状態・演算子の範囲は狭まらない。

基底順序は要件の 6.2 節の mixed-radix とし、右端の因子の基底 index が最も速く変化する。要素数は局所基底要素数の積から導出する。Grouping は括り方だけを表し、同じ基本因子・局所基底・順序なら、複合基底や座標を変えない。空の tensor product の基底は `{1}`、単因子の場合はその因子の基底とする。

Graded な演算子基底の合成は、[複合空間の合成則](composite-expression.md)に従う。演算子の tensor 記法は数学的な規則を表し、独立した tensor product 操作・節点を追加しない。全基底を一度に materialize せず、必要な要素・係数だけを処理する。基底選択によって Hilbert 空間の因子順序や互換性は変更しない。

### 5.2. 展開結果は通常の式木とする

基底は展開操作への入力とし、式全体への展開結果は選択した基底要素で表した通常の式木とする。局所基底規則の返す `LinearCombination` は、その式を組み立てるための受け渡し型とする。結果に基底の識別情報や「展開済み」という特別な状態を保持することは要求しない。演算子・状態の表現が変わる操作とし、入力の式は変更しない。結果は Index・局所構造・確定済みの所属空間や作用空間を保持する。source の自動保持は要求しない。

展開結果にも通常の積・作用・内積・trace、および指定基底への展開を適用できる。別の基底へ表現を変える場合は、その基底を指定して再展開する。前の基底の識別情報や、式木に対する独立した基底変更機構は必要としない。直接の展開と再展開は数学的に同じ座標を与える契約とし、浮動小数点の演算順序による差は既存の数値規約に従う。

式から係数列や行列へ export する場合は、その数値を解釈できるよう基底と順序を確定する。この数値表現の契約は、通常の式木に基底情報を保持させることとは区別する。[写像の表現行列](representation-matrix.md)は future work とし、通常の演算と基底展開・係数取得を組み合わせて構成する数学的契約を将来向けに保持する。今回の基底処理の前提条件にはしない。

## 6. PauliBasis の例と検証条件

`PauliBasis` が spin 演算子を対象とする `Basis` を実装し、`{I,Sx,Sy,Sz}` をこの順序の基底とする例を用いる。名称は設計を説明するための例とし、具体的な公開型の名前を確定しない。Spin 演算子の規約は要件の 2.3 節に従う。

| Primitive | 基底展開 | 基底順序番号 |
| --- | --- | --- |
| `I` | `I` | `0` |
| `Sx` | `Sx` | `1` |
| `Sy` | `Sy` | `2` |
| `Sz` | `Sz` | `3` |
| `S+` | `Sx + i Sy` | 存在しない |

列挙結果は `I, Sx, Sy, Sz` とする。対応する局所状態空間の次元は `d = 2` なので、全演算子基底の要素数は `d² = 4` と導出する。列挙・順序番号・展開の整合性を確認し、`S+` と `Sx + i Sy` の基底座標が一致することも検証対象とする。

Step 2 では、spin-half の `SzBasis` が状態 primitive の線型結合、`CartesianBasis`・`LadderBasis` が演算子 primitive の線型結合を返し、それぞれを `map` と共通 constructor で局所式へ取り込めることを確認する。各要素が選択基底に限られること、単精度・倍精度で現行の展開規則と基底順序が維持されること、および非公開の局所代数・非正規直交基底も接続できることを検証する。

式全体の展開では、同じ基底で `S+ + S-` が `2 Sx`、`Sx Sx` が `I/4` へ展開されることを確認する。前者は基底要素の係数結合、後者は必要な局所積の評価を含む。展開で入力の式が変更されず、結果が選択した空間の情報を保持することと、通常の作用・内積・trace にこの基底展開を強制しないことを検証する。

展開結果に基底情報を要求せず、通常の式として評価・再展開できることを確認する。例えば `Sx` を `{I,S+,S-,Sz}` で `(S+ + S-)/2` に展開し、`{I,Sx,Sy,Sz}` で再展開すると `Sx` と同じ座標を得る。複合基底では、括り方によらない要素・座標、右端の因子が最も速く変化する順序、および空・単因子の基底も検証する。

## 7. 採用方針と実装時の具体化

2026-10-27に、Step 5 の残る推奨案を採用した。`expand_in` と集約済み座標の取得 API で内部の係数処理を共有し、基底番号をキーに疎に集約して基底順で返す。座標には対象空間・共通局所基底・因子順序を対応付け、通常の式木へそれらを付随させない。空間不整合・不正な基底番号や展開先・次元 overflow を区別し、Index と数値能力の制約は必要な操作にだけ要求する。実装は局所式から複合式へ進める。

具体的なメソッドのシグネチャ、座標番号・返却コンテナ・エラーの型、基底情報の受け渡し、および内部の走査・保持・共有は、この採用方針に従って実装時に定める。詳細は [Step 5 の一時設計メモ](../step-5-design.md)に記録する。

局所基底規則が薄い `LinearCombination` を返すこと、`Basis` の直接利用と `StateBasis`・`OperatorBasis` の削除、および Step 2 での `map` による式木との接続は確定事項とする。後続の設計でも、基底を定義する struct と三つの能力、およびprimitive の span の次元からの要素数の導出を維持する。marker trait の削除後も、基底の線型独立性・完全性、要素数が状態では `d`、全演算子空間では `d²` となる数学的契約と検証条件は維持する。
