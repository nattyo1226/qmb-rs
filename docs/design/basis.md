# 基底の数学的能力

更新日: 2026-10-15

## 1. 対象と合意した契約

本書は、[要件](../requirements.md)と[アーキテクチャ概要](../architecture.md)に基づき、状態・演算子の局所 primitive に対応する基底の定義と数学的能力を定める。[局所 primitive・式木の数学的能力](primitive-expression.md)における基底との接続の詳細設計である。

基底の定義は `PauliBasis` のような struct が表し、`Basis<Primitive>` を実装する。その実装が、特定の primitive たちを基底とする規則と、各 primitive をその基底へ展開する手続きを提供する。利用者が基底要素の配列や集合そのものを入力することは要求しない。

基底要素は対応する primitive の部分集合とし、線型独立かつ対象空間全体に完全であることを要求する。基底要素として一般の式を指定することは本契約に含めない。正規直交性は要求しない。Primitive 全体は線型従属でもよい。

基底は、対応する[局所構造](local-structure.md)、その定義パラメータ、および対象が状態か演算子かを識別できるものとする。その具体的な関連付け方は API 設計に委ねる。選択基底は局所構造や自由度の Index の同一性とは区別する。

## 2. Basis の三つの能力

| 能力 | 入力 | 結果・契約 |
| --- | --- | --- |
| Primitive の基底展開 | 対応する対象空間の primitive | 選択された基底 primitive の有限線型結合 |
| 基底順序番号の取得 | primitive | 選択された基底要素である場合に、その順序番号を返す。基底要素でなければ番号は存在しない |
| 順序付きの列挙 | 基底の定義・パラメータ | 基底順序に従って、基底 primitive を必要に応じて列挙する |

基底を `B = {b_0, …, b_{n−1}}` とすると、任意の対応する primitive `p` について以下を与える。

```math
p=\sum_{\mu=0}^{n-1}c_\mu(p)b_\mu.
```

線型独立性によって、この展開の係数は一意となる。展開は対象全体を正確に表し、射影や成分の切り捨てを行わない。基底要素でない primitive も展開できるが、それ自体を指す基底順序番号は返さない。

順序番号は選択基底の中での zero-based な座標番号とし、primitive の表示名や値の大小から暗黙に決めない。自由度を識別する Index とは別の概念である。番号が存在しないことの返却方法、メソッド名、および Rust のシグネチャは未決とする。

列挙は全要素の一括生成・保持を要求しない。順序番号から primitive を得る操作は列挙から導出でき、Basis の必須の独立能力にはしない。列挙の内部表現と基底 primitive の共有実体の管理方法は API・内部実装の設計に委ねる。

## 3. 要素数の導出

基底要素数は、対応する局所構造と対象種別から共通機構で導出する。局所 Hilbert 空間の次元を `d` としたとき、以下の要素数になる。

| 対象 | 基底要素数 |
| --- | --- |
| 状態空間 | `d` |
| 全演算子空間 | `d²` |

Basis に独立した要素数の提供を要求しない。要素数を得る便利な操作を設ける場合も、上記の情報から導出する。primitive の個数や、列挙を完走して数えた値を要素数の定義にはしない。

この契約は対象空間全体に完全な基底を前提とする。要件に従い、部分空間基底・射影、および fermion の even 部分だけへの制限は初期版で扱わない。要素数を表す整数型などの具体的な API は未決とする。

## 4. 能力間の整合性

- 列挙は基底要素を一度ずつ返し、第 `k` 要素の基底順序番号は `k` とする。
- 列挙順序と順序番号は、同じ基底定義・パラメータのもとで一致する。
- 列挙される要素数は、局所構造と対象種別から導出した数と一致する。
- 基底要素自身の展開は、係数 `1` のその要素となる。
- 任意の primitive の展開結果に現れる primitive は、選択された基底要素に限る。
- Primitive 間の線型関係を保存し、同じ数学的対象を表す式から同じ基底座標を得る。

これらと基底の線型独立性・完全性は、基底実装が満たす数学的な契約と検証対象である。全 primitive の列挙や、任意の実装に対する実行時の自動証明は要求しない。数値精度・特殊値・近似比較は既存要件に従う。

## 5. 式・座標取得・数値変換との責任分担

Basis は primitive 一つに対する展開を提供し、core の共通機構が線型性を用いて式全体へ拡張する。展開された基底 primitive の順序番号を使って係数を座標へ対応付ける。

内積、Gram 行列、および双対基底は、展開手続きを実装するために利用できるが、Basis が提供する必須の独立能力とはしない。直接の展開規則を提供できれば座標を取得できる。演算子内積を使う場合は、既存要件の非正規化 Hilbert–Schmidt 内積 `Tr(A†B)` に従う。

基底展開による座標取得は、通常の積・作用・内積・trace・簡約の一般経路から分離する。Source の構造比較に primitive 間の一般の線型関係を導入しない。数値変換などで座標を要求した時点で必要な部分を展開し、完全な密・疎行列を中間表現として要求しない。

複合基底の構成と順序は、要件の 6.1–6.2 節に従う。全基底を一度に materialize せず、必要な要素・係数だけを処理する。局所基底の選択によって、Hilbert 空間の因子順序や空間の互換性は変更しない。

## 6. PauliBasis の例と検証条件

`PauliBasis` が `Basis<SpinHalfOperatorPrimitive>` を実装し、`{I,Sx,Sy,Sz}` をこの順序の基底とする例を用いる。名称は設計を説明するための例とし、具体的な公開型の名前を確定しない。Spin 演算子の規約は要件の 2.3 節に従う。

| Primitive | 基底展開 | 基底順序番号 |
| --- | --- | --- |
| `I` | `I` | `0` |
| `Sx` | `Sx` | `1` |
| `Sy` | `Sy` | `2` |
| `Sz` | `Sz` | `3` |
| `S+` | `Sx + i Sy` | 存在しない |

列挙結果は `I, Sx, Sy, Sz` とする。対応する局所状態空間の次元は `d = 2` なので、全演算子基底の要素数は `d² = 4` と導出する。列挙・順序番号・展開の整合性を確認し、`S+` と `Sx + i Sy` の基底座標が一致することも検証対象とする。

## 7. 未決事項

- Basis と局所構造・定義パラメータ・対象種別を関連付ける具体的な方式
- 展開結果、順序番号が存在しない場合、および遅延列挙の Rust の型・公開 API
- 基底 primitive の保持・共有と、展開・列挙の具体的な内部実装

これらの決定では、基底を定義する struct と三つの能力、および局所構造からの要素数の導出を維持する。
