# 局所構造の設計

更新日: 2026-10-22

## 1. 対象と検討状況

本書は、局所構造が保持する空間の情報、状態・演算子 primitive の数学的能力の整合性、および局所構造同士の一致条件を記録する。[要件](../requirements.md)の責任分離を前提とし、同じ定義・定義パラメータを持つ局所構造を一致とする。

局所構造・primitive の能力契約と、それを式・空間へ拡張する共通処理は `qmb-core` が所有する。spin-1/2 などの具体的な局所構造・primitive・規則・基底は専用 crate が実装し、core の共通型を直接利用する。

局所構造は、局所 Hilbert 空間と、その上で実現される代数・表現を定める。対応する状態・演算子 primitive と、それらが持つ数学的能力を関連付け、同じ局所表現を記述するための整合性を要求する。Index と選択基底は、局所構造とは区別する。

Step 2 の Rust API は、係数型に依存しない `LocalStructure` に状態・演算子の関連型と `DIMENSION` だけを置く。恒等演算子の規則は `Identity<T>: LocalStructure` に分離し、`LinearCombination<Self::Operator, T>` を返す。積・作用・内積・随伴・trace の能力は必要なメソッドで要求し、式の保持・構築へ不要な数値制約を波及させない。この分離は採用済みの設計であり、現行コードからの移行は Step 2 で行う。

初期版の一つの系は、同じ局所構造型 `L` で表す一種類の局所構造だけで構成する。異種局所構造、すなわち異なる定義・定義パラメータの局所構造を一つの系に混在させる機能は後続へ延期する。別の型による独自局所構造の実装は、それだけを使う別の系で利用・検証できる。同じ構造の独立した因子は Index で区別する。

## 2. 空間の情報と能力の関連付け

| 情報・責任 | 内容 |
| --- | --- |
| 局所状態空間の次元 | 有限次元 `d` を提供する。primitive の個数とは区別する |
| Primitive の所属 | 対応する状態・演算子 primitive の型と有効な値を定める |
| 代数・表現のパラメータ | spin の `S` など、同じ型でも異なる局所表現を区別する情報を保持する |
| Scalar の整合性 | 積・作用・内積・随伴・trace と線型結合で、対応する複素数型・数値精度を用いる |
| 恒等演算子の取得 | 同じ局所構造の演算子 primitive またはその有限線型結合として取得できるようにする |
| Grading〈対応する場合〉 | 状態・演算子 primitive の parity と局所 parity 演算子を関連付ける |
| 基底との接続 | 選択した基底への正確な展開と座標取得を可能にする |

状態・演算子 primitive の有限線型結合はそれぞれ対象空間全体を張る。primitive の線型独立性は要求しない。これらの情報をすべて一つの実体に格納することや、全 primitive・積テーブルを一度に列挙・保持することは要求しない。

積の Product は演算子 primitive 側、演算子の作用を受ける Act は状態 primitive 側の能力とし、局所構造が対応する primitive と能力を関連付ける。Act は状態を受け手、演算子を引数として演算子の左作用を計算する。内積・随伴・trace を含む能力の詳細と、core の共通の式木への拡張は、[局所 primitive・式木の数学的能力](primitive-expression.md)に定める。

## 3. 数学的能力の整合性

以下の `A,B,C` は同じ局所構造の演算子、`ψ,φ` はその状態、`I` は恒等演算子とする。primitive の線型結合も含め、次の契約を要求する。

- 閉性・所属の保存: Product・Act・随伴の結果は同じ局所構造に属する。対応する型と表現パラメータが整合することを要求する。
- 線型性: 積と作用はそれぞれの引数について線型、内積は第一引数について共役線型・第二引数について線型、随伴は共役線型、trace は線型とする。
- 積の結合則と作用の整合性: `(AB)C = A(BC)` および `(AB)ψ = A(Bψ)` を満たす。
- 単位元: `IA = AI = A` および `Iψ = ψ` を満たす。
- 内積: 共役対称性と、状態空間上での正定値性を満たす。非独立な primitive では、非零の係数列でも zero state を表し得る。
- 随伴: 内積・作用との以下の関係、および `(A†)† = A`、`(AB)† = B†A†` を満たす。
- Trace: 局所 Hilbert 空間上の通常の非正規化 trace と一致し、`Tr(I) = d` を満たす。
- 線型関係の保存: 同じ状態・演算子を表す異なる primitive の線型結合に演算を適用したとき、数学的に同じ結果を得る。展開係数や式木の構造の一意性は要求しない。
- Grading〈対応する場合〉: homogeneous な primitive の parity と局所演算規則が整合する。因子間の符号処理は共通の複合代数機構に委ねる。

```math
\langle\phi,A\psi\rangle=\langle A^\dagger\phi,\psi\rangle.
```

これらは局所実装が満たす数学的な契約と検証対象である。任意の実装に対して結合則などを実行時に自動証明する機構は要求しない。所属・表現パラメータの不一致は、判定に必要な情報が揃った時点で、4 節の定義・定義パラメータの一致に基づいて検証する。定義の識別方式などの具体的な実装は今後定める。

等式は数学的な意味について要求し、浮動小数点計算のビット単位の一致とは区別する。数値精度、特殊値、および近似比較は要件の 4.1 節・5.6 節に従う。

## 4. 局所構造の一致条件

二つの局所構造は、同じ定義と同じ定義パラメータを持つ場合に一致とする。同じ定義には、局所空間・代数・表現、primitive の意味、および内積・Product・Act・随伴・trace・恒等演算子・grading などの数学的規約が含まれる。定義パラメータは、その定義のもとで空間や演算規則を定める値であり、spin の `S` などを含む。

別々に構築した対象や、保存した対象を復元したものでも、同じ定義・定義パラメータを持つなら一致する。次元や実装している trait の種類が一致することだけでは、局所構造の一致を認めない。同じ定義・定義パラメータを持つ実装は、同じ次元と primitive の解釈を与え、3 節の数学的能力を整合させる契約を満たす必要がある。

Index、site、表示名、選択基底とその列挙順序、メモリ上の object identity、および共有方法は一致条件に含めない。演算を公式で計算するかテーブルを参照するかといった実装方法も比較対象としない。局所規則が返す線型結合の項列や、取り込み後の式木の形を比較することは要求しない。

数学的同型の判定や primitive の自動対応付けを、一致判定に導入しない。異なる定義や定義パラメータを、同じ次元や数学的な同型だけから一致と扱わない。許容誤差による近似一致も局所構造の一致には用いない。式の表現に用いる基底の変更は、別の基底を指定した通常の再展開で扱い、式木のための独立した基底変更機構は要求しない。詳細は [基底展開の契約](basis.md#52-展開結果は通常の式木とする)に従う。

数値精度の互換性は、局所構造の定義・定義パラメータの一致とは別に、既存要件の数値規約に従って検証する。数学的な構造が一致しても、異なる数値精度の対象を同じ演算で混在させない。

| 比較する対象 | 局所構造の一致 |
| --- | --- |
| 同じ定義・定義パラメータで別々に構築した対象 | 一致 |
| 同じ定義・定義パラメータを保持して復元した対象 | 一致 |
| 同じ定義・定義パラメータで、選択基底・表示名・共有方法だけが異なる対象 | 一致 |
| 異なる定義の対象。次元が同じ場合も含む | 不一致 |
| 同じ定義で、定義パラメータが異なる対象 | 不一致 |

定義を識別する具体的な方式と、将来の定義パラメータの保持形式・公開 API は後続段階で具体化する。Step 2 の固定次元・静的な primitive の関連付けと、演算能力を分離する trait 構成は採用済みとする。

## 5. Index の契約との接続

[Index の契約](index.md)では、Index の一致と局所構造の一致を別に判定する。Index は局所構造や次元を持たず、自由度や Index を付与した局所状態・演算子が局所構造を保持する。Index と局所構造の対応を全体で登録・固定する機構は設けず、合成・埋め込み・評価に必要な整合性は操作の対象から検証する。

4 節の定義・定義パラメータによる一致条件を、その局所構造の照合に用いる。局所構造が一致しても、異なる Index を持つ自由度は独立した因子である。
