# 初期版の提供範囲と完成条件

更新日: 2026-10-25

## 1. 初期版の目的と文書の位置付け

初期版は、spin-1/2 の 1D Chain を代数的に構築・評価し、密・疎の数値表現へ変換する一連の流れが完結する版とする。[要件](../requirements.md)と[アーキテクチャ概要](../architecture.md)に記録した数学的契約のうち、本書の提供範囲を初期版の必須実装とする。

具体的な Rust の型・API・内部表現は、採用済みの方針に従って各段階で具体化する。数値 backend は後続段階で選定する。本書は完成条件を定めるものであり、実装済みであることを示すものではない。後続機能のために既に合意した数学的契約は保持する。

## 2. 提供範囲

| 対象 | 初期版で提供するもの |
| --- | --- |
| Index・自由度 | core では Index 型をジェネリックに扱い同一性を照合する。basic では UUID による具体型 Id128 と new・Default による seed 指定不要の独立した発行を提供する。再利用、局所構造との組による自由度の構築、局所式への明示的な Index の付与 |
| 局所構造 | Spin-1/2。状態 primitive は `up, down`、演算子 primitive は `I, Sx, Sy, Sz, S+, S-`。局所積・作用・内積・随伴・trace・恒等演算子と、その整合性 |
| 拡張性 | ユーザ定義の有限次元局所構造・primitive・規則・基底を、別の系で単独利用できること |
| Hilbert 空間 | 基本自由度を表す葉（Factor）と入れ子 Tensor を同じ HilbertSpace 型で扱い、独立した Dof 型は設けない。同じ局所構造の因子、ordinary tensor product、次元、構成要素・Index の列挙、互換性判定、部分系判定、空・単因子の契約 |
| 状態・演算子式 | 合意済みの加算・scalar multiplication・zero・identity、状態の tensor product、演算子積、配置・束縛、作用・内積・随伴・full/partial trace |
| 導出する操作 | Norm・正規化、期待値・正規化期待値、commutator / anticommutator、Hilbert–Schmidt 内積 |
| 基底 | 順序付き状態基底 `{up,down}`、演算子基底 `{I,Sx,Sy,Sz}` と `{I,S+,S-,Sz}`、それらの tensor product 基底。指定基底への展開・再展開・係数取得 |
| 写像の表現行列 | 基底列挙・通常の演算・出力基底への展開と係数取得を組み合わせる共通操作。線型・共役線型・双線型・半双線型な作用を扱い、専用 trait の実装は要求しない |
| 数値 export | 状態の密・疎ベクトル、演算子の密・疎行列。外部数値ライブラリへの必要最小限の接続 |
| Geometry・配置 | 1D Chain の open / periodic。既存 Factor・Tensor からの配置、Site 数・各 Site 共通の自由度数から Default による Index 発行。Site は Vec の位置、grouping は HilbertSpace で表し、内部ラベルは導入しない |
| 数値精度 | 単精度・倍精度の複素数。精度の混在を拒否し、変換は明示的に行う |

演算子・状態の具体的な規約と各操作の空間選択は要件に従う。展開結果は基底情報を持たない通常の式木とし、入力の式を変更しない。状態式の `act` は遅延した作用を構築し、`evaluate` は基底を指定しない局所規則による評価を行う。通常の作用・内積・trace に基底展開や行列化を要求しない。

Geometry の標準実装は 1D Chain のみとする。生成時に局所構造型を指定し、Site 順の Vec に HilbertSpace を保持する。各空間の葉の順序が Site 内の自由度順序となる。新たに全 Hilbert 空間を構成する際は Site 順・葉の順に並べ、既存空間の因子順序は暗黙に変更しない。近接関係は Site 番号のペアから Index の全組合せまたは同じ位置同士へ変換できる。詳細は [Chain の配置契約](geometry.md#41-初期版の-1d-chain-の配置規則)に定める。

標準提供する局所構造は spin-1/2 のみとする。非公開の別の局所代数や非正規直交基底による検証は、拡張性の完成条件であり、追加の builtin を公開する要求とは区別する。

一つの系の全基本因子は、同じ局所構造型 `L` で表す一種類の局所構造とする。異種局所構造の混在・合成は初期版に含めず、そのための型消去・保持機構も要求しない。同種因子の入れ子、一つの Site への複数自由度の配置、因子ごとに異なる基底を選ぶことは引き続き扱う。

## 3. 完成条件

### 3.1. 代表シナリオが完結する

実行可能な例で、次の処理を一貫して行えることを要求する。

1. Open または periodic な 1D Chain に spin-1/2 を配置し、全 Hilbert 空間を構成する。
2. 近接関係から、通常の局所演算子積の有限和として Heisenberg Hamiltonian を構築する。
3. Neel 状態を積状態として構築し、行列化せずに作用・内積から期待値を求める。
4. 同じ状態・演算子を一貫した基底順序で密・疎の数値表現へ export する。
5. 小規模系で、代数計算・密表現・疎表現から得た結果を比較する。

Open chain の解析的な期待値、実数の結合定数による Hermiticity、および `0-site` の特例は要件の 8 節に従う。各精度の数値比較では許容誤差を明示する。

### 3.2. 基本契約が検証されている

小規模系について、積・作用・内積・随伴・full/partial trace の結果を、独立に構成した行列による参照計算と比較する。結合則、作用と積、内積と随伴、trace と縮約の整合性も確認する。

空の空間、zero・identity、入れ子、各 Site に複数の自由度を持つ配置、および長さ `0,1,2` の chain を含める。Periodic chain の小規模系は、self-loop・重複辺を作らない既存の規約に従う。

### 3.3. 基底展開と表現行列が一貫する

別基底への再展開と直接の展開が数学的に一致し、展開後の式を基底情報なしで通常の演算に利用できることを確認する。複合基底の要素・座標・順序が grouping に依存しないことも検証する。

写像の表現行列から求めた結果は、直接の演算と一致するものとする。共役線型・双線型・半双線型な作用について、虚部を持つ入力係数、各入力の共役指定、複数入力の列順序、および非正規直交基底の座標・Gram 行列を検証する。全基底や巨大な積テーブルの一括生成は完成条件に含めない。

### 3.4. 抽象化と lazy 評価が機能する

非公開の別の有限次元局所代数を、共通処理への代数種別の追加分岐なしで実装し、その代数だけで構成する独立した系に対し、共通の式による作用・trace・基底展開・数値 export を検証する。spin と同じ系に混在させることは完成条件に含めない。非正規直交基底でも、正しい座標と内積・norm を得ることを確認する。

式の構築だけで全体の展開・行列生成・変更されない operand 全体の不要な deep copy が起きないことを確認する。不変な空間・式・primitive の共有と、入力を変更しないことを検証する。`act` のチェーンの作用順序と、基底を指定しない `evaluate` を確認する。密表現を明示的に要求するまで Hilbert 空間の次元に比例する密な領域を確保しない契約を守り、一般の入力に対する最適な計算量は要求しない。

### 3.5. 利用例と不正入力の検証が揃っている

代表シナリオを実行可能な利用例として提供する。少なくとも Index の重複、局所構造・空間・精度の不整合、無効な縮約対象、zero-norm state の正規化、配置数の過不足、Site 間の Index 重複、および範囲外の Site 指定を検出する。必要な情報が揃う時点での検証と、元の対象を変更しない契約も確認する。

Index 発行後の配置と空間構築で同じ Index が保持されること、参照・列挙・複製で Index を再発行しないこと、Site 順序と構築後の不変性も検証する。Geometry を跨ぐ所属チェックは要求しない。

## 4. 後続へ延期するもの

- bra 型・構築 API と内部ラベル。braket は内積で計算し、grouping は既存の HilbertSpace を用いる。

- 異種局所構造を一つの系に混在・合成する機能と、そのための型消去・保持機構。
- Graded tensor product・fermion の実装。合成・作用・随伴・通常の trace に関する既存の数学的契約は保持する。
- Spin-1/2 以外の builtin algebra、1D Chain 以外の Geometry。
- source の自動保持、式の構造比較、および式表示 API。入力の不変性と不変実体の共有は維持する。
- 保存・復元、個別の簡約ルールを選択して適用する操作、評価結果のキャッシュ、並列評価・スレッド間共有。
- ML・自動微分 module、tensor network・MPS・MPO、GPU・分散計算などへの接続。
- 要件の 9 節にある部分空間・射影、因数分解、permutation など、既に対象外または将来候補として整理した機能。

Index の一意性・同一性、不変な実体の共有、および個別ルール適用を必要としない内部の分配・局所積・係数処理は維持する。延期対象を実装していないことを理由に、初期版の上記の完成条件を省略しない。

## 5. 残る実装設計

crate 分割と実装順序は、[実装計画](../implementation-plan.md)に定める。抽象契約・有限線型結合・共通式木・ジェネリックな Index の照合・空間・評価・基底処理は `qmb-core` に集約し、UUID の具体型と発行の `qmb-basic`、具体的代数の `qmb-spin-half`、幾何と Site への配置の `qmb-geometry`、数値変換の `qmb-export`、norm・状態の正規化の `qmb-normalize`、利用窓口の `qmb` と合わせて計画上は7 crate を構成する。basic・spin・geometry・export・normalize は core に依存し、spin の構築 utility は geometry の公開契約を利用する。core はそれらに依存しない。UUID・乱数源の依存は core に置かず、`no_std + alloc` を維持する。normalize は std を利用できる。

式木には `ScaleExpr`・`SumExpr`・`ProductExpr`・`ActExpr`・`AdjointExpr` の共通パーツを用いる。`LinearCombination<P, C>` は薄い有限線型結合型として維持する。Step 2 で演算 trait を係数全体 `C` と関連型 `Term`・`Act::Operator` に揃え、core・spin-half の局所規則・恒等演算子・局所基底展開の線型結合を `map` と共通 constructor で式木へ取り込む。式全体の基底展開・複合基底・座標取得は Step 5 で実装する。不変な式節点・primitive は式ハンドルの `Arc` で共有し、同じハンドルを再利用した部分を複製しない。

Step 2 の採用済み方針として、`LocalStructure` を係数型に依存しない関連型・次元の定義とし、恒等演算子の規則は `Identity<C>` に分離する。共通パーツは `expr::parts` で保持内容も公開し、式ハンドルを再公開する。節点 enum と共有の内部表現は非公開とする。項型 `Term<P, C>` は `ScaleExpr<P, C>` の別名に統合し、要素名を `operand` に揃える。既存の線型結合の構築・走査 API は維持する。`StateBasis`・`OperatorBasis` は削除し、状態には `Basis<L::State, C>`、演算子には `Basis<L::Operator, C>` を直接使う。次元からの基底要素数の取得と基底の数学的契約は維持する。

評価器は状態評価・演算子の作用・演算子項の走査を分担し、状態の作用評価に Product 能力を要求しない。型制約は必要な操作にだけ付け、演算子構文は所有値・借用値の4通りに対応する。評価と最後の所有者になった式節点の破棄は反復的に行う。長い式の評価・破棄、共有、不要な primitive 複製の抑制、空・単一項のコンテナ無確保を検証条件とし、map 全般の無確保や特定の実行時間は保証しない。

Step 3 の空間・複合式・共有・束縛・エラー・評価経路は [採用済みの実装方針](../step-3-design.md)に従う。局所構造は型 `L` による固定定義、空間は `Arc` の共有ハンドルとし、総次元の overflow は取得時に検出する。状態は常に所属空間を持ち、演算子の束縛は外側のハンドルへ集約する。検証が必要な複合操作は `Result` を返し、作用・内積・full trace を目的別に評価する。

Norm・正規化・正規化期待値は、[Step 4 の合意事項](../step-4-decisions.md)に従って局所式・複合式に実装する。core の libm は任意 feature、qmb では既定で有効とする。Heisenberg・Neel utility は qmb-spin-half に置き、qmb は再公開と縦断例を提供する。Partial trace・基底処理は Step 5、数値 backend は Step 6 で具体化し、初期版の必須範囲を維持する。bra 型・構築 API は初期版では導入しない。

上記は Step 4 の実装を記録したものである。2026-10-25 に採用した[係数型の方針](../refactoring-coefficient-proposal.md)では、係数全体 C と個別の能力契約へ移行し、norm・normalized・正規化期待値と NormalizationError を qmb-normalize へ移す。内積・期待値・norm squared・スカラー除算は core に残し、Float は平方根を使う実数型 R に要求する。この移行は実装済みであり、Norm／Normalize／NormalizedExpectation／NormalizedExpectationIn を import して呼び出す。qmb の既定 feature は normalize、旧 libm はその互換 alias とする。

非公開の節点・作業領域・補助関数、メソッド名・型引数・シグネチャの詳細、および追加依存の選択は採用済み方針の範囲で各段階に定める。Step 2 の局所式・評価と API の移行、および Step 3 の空間・配置・複合評価と basic の UUID Index は実装済みである。Step 4 以降の機能と初期版全体の完成とは区別する。
