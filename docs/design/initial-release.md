# 初期版の提供範囲と完成条件

更新日: 2026-10-27

## 1. 初期版の目的と文書の位置付け

初期版は、spin-1/2 の 1D Chain を代数的に構築・評価し、密・疎の数値表現へ変換する一連の流れが完結する版とする。[要件](../requirements.md)と[アーキテクチャ概要](../architecture.md)に記録した数学的契約のうち、本書の提供範囲を初期版の必須実装とする。

具体的な Rust の型・API・内部表現は、採用済みの方針に従って各段階で具体化する。数値 backend は後続段階で選定する。本書は完成条件を定めるものであり、実装済みであることを示すものではない。後続機能のために既に合意した数学的契約は保持する。

## 2. 提供範囲

| 対象 | 初期版で提供するもの |
| --- | --- |
| Index・自由度 | core では Index 型をジェネリックに扱い同一性を照合する。basic では UUID による具体型 Id128 と new・Default による seed 指定不要の独立した発行を提供する。再利用、局所構造との組による自由度の構築、局所式への明示的な Index の付与 |
| 局所構造 | Spin-1/2。状態 primitive は `up, down`、演算子 primitive は `I, Sx, Sy, Sz, S+, S-`。局所積・作用・内積・随伴・trace・恒等演算子と、その整合性 |
| 拡張性 | ユーザ定義の有限次元局所構造・primitive・規則・基底を、別の系で単独利用できること |
| Hilbert 空間 | 基本自由度を表す葉（Factor）と入れ子 Tensor を同じ HilbertSpace 型で扱い、独立した Dof 型は設けない。同じ局所構造の因子、ordinary tensor product、次元、構成要素・Index の列挙、互換性判定、部分系判定、空・単因子の契約 |
| 状態・演算子式 | 合意済みの加算・scalar multiplication・zero・identity、状態の tensor product、演算子積、配置・束縛、作用・内積・随伴・full trace |
| 導出する操作 | Norm・正規化、期待値・正規化期待値、commutator / anticommutator、Hilbert–Schmidt 内積 |
| 基底 | 順序付き状態基底 `{up,down}`、演算子基底 `{I,Sx,Sy,Sz}` と `{I,S+,S-,Sz}`、それらの tensor product 基底。指定基底への展開・再展開・係数取得 |
| 数値 export | 状態の密・疎ベクトル、演算子の密・疎行列。外部数値ライブラリへの必要最小限の接続 |
| 幾何・配置 | 1D Chain の open / periodic。Site ごとの所有 Index 列の入力と、Site 数・各 Site 共通の自由度数から Default による Index 発行。Chain は Index 列と境界条件を直接保持し、空間・grouping は利用側が管理。内部ラベルは導入しない |
| 数値精度 | 単精度・倍精度の複素数。精度の混在を拒否し、変換は明示的に行う |

演算子・状態の具体的な規約と各操作の空間選択は要件に従う。展開結果は基底情報を持たない通常の式木とし、入力の式を変更しない。状態式の `act` は遅延した作用を構築し、`evaluate` は基底を指定しない局所規則による評価を行う。通常の作用・内積・trace に基底展開や行列化を要求しない。

標準の幾何は 1D Chain のみとする。2026-10-26 に、Site ごとの Index 列 `Vec<Vec<I>>` と境界条件を直接保持し、Geometry 構造体と空間保持を廃止する方針を採用した。2026-10-27に実装へ反映した。Site 順・Site 内の順序を保持し、空間の構築・保持・全体の因子順序・grouping・配置と束縛は利用側が担当する。既存空間の因子順序は暗黙に変更しない。近接関係は Site 番号のペアから Index の全組合せまたは同じ位置同士へ借用列挙できる。詳細は [Chain の配置契約](geometry.md#41-初期版の-1d-chain-の配置規則)に定める。

標準提供する局所構造は spin-1/2 のみとする。非公開の別の局所代数や非正規直交基底による検証は、拡張性の完成条件であり、追加の builtin を公開する要求とは区別する。

一つの系の全基本因子は、同じ primitive 型 S・O で表す一種類の局所代数とする。異種局所構造の混在・合成は初期版に含めず、そのための型消去・保持機構も要求しない。同種因子の入れ子、一つの Site への複数自由度の配置は引き続き扱う。複合基底には一つの局所基底を全基本因子へ共通に適用し、因子ごとに異なる基底を選ぶことは扱わない。別基底への再展開は引き続き扱う。採用した方針は [Step 5 の一時設計メモ](../step-5-design.md)に記録する。

## 3. 完成条件

### 3.1. 代表シナリオが完結する

実行可能な例で、次の処理を一貫して行えることを要求する。

1. Open または periodic な 1D Chain に spin-1/2 を配置し、全 Hilbert 空間を構成する。
2. 近接関係から、通常の局所演算子積の有限和として Heisenberg Hamiltonian を構築する。
3. Neel 状態を積状態として構築し、行列化せずに作用・内積から期待値を求める。
4. 同じ状態・演算子を一貫した基底順序で密・疎の数値表現へ export する。
5. 小規模系で、代数計算・密表現・疎表現から得た結果を比較する。

Open chain の解析的な期待値、実数の結合定数による Hermiticity、および `0-site` の特例は要件の 8 節に従う。各精度の数値比較では許容誤差を明示する。

### 3.2. 基本契約が検証されている

小規模系について、積・作用・内積・随伴・full trace の結果を、独立に構成した行列による参照計算と比較する。結合則、作用と積、内積と随伴、および trace の巡回性も確認する。

空の空間、zero・identity、入れ子、各 Site に複数の自由度を持つ配置、および長さ `0,1,2` の chain を含める。Periodic chain の小規模系は、self-loop・重複辺を作らない既存の規約に従う。

### 3.3. 基底展開・再展開と座標取得が一貫する

別基底への再展開と直接の展開が数学的に一致し、展開後の式を基底情報なしで通常の演算に利用できることを確認する。複合基底の要素・座標・順序が grouping に依存しないことも検証する。

取得した座標から状態・演算子を再構成し、元の式と数学的に一致することを確認する。非正規直交基底でも展開座標と内積値を区別する。全基底の一括生成は完成条件に含めない。

### 3.4. 抽象化と lazy 評価が機能する

非公開の別の有限次元局所代数を、共通処理への代数種別の追加分岐なしで実装し、その代数だけで構成する独立した系に対し、共通の式による作用・trace・基底展開・数値 export を検証する。spin と同じ系に混在させることは完成条件に含めない。非正規直交基底でも、正しい座標と内積・norm を得ることを確認する。

式の構築だけで全体の展開・行列生成・変更されない operand 全体の不要な deep copy が起きないことを確認する。不変な空間・式・primitive の共有と、入力を変更しないことを検証する。`act` のチェーンの作用順序と、基底を指定しない `evaluate` を確認する。密表現を明示的に要求するまで Hilbert 空間の次元に比例する密な領域を確保しない契約を守り、一般の入力に対する最適な計算量は要求しない。

### 3.5. 利用例と不正入力の検証が揃っている

代表シナリオを実行可能な利用例として提供する。少なくとも Index の重複、局所構造・空間・精度の不整合、zero-norm state の正規化、配置数の過不足、Site 間の Index 重複、および範囲外の Site 指定を検出する。必要な情報が揃う時点での検証と、元の対象を変更しない契約も確認する。

Index 発行後の配置と空間構築で同じ Index が保持されること、参照・列挙・複製で Index を再発行しないこと、Site 順序と構築後の不変性も検証する。Chain の保持・借用列挙へ Clone を要求せず、所有データの複製や借用 Index からの空間構築にだけ要求できることを確認する。Chain を跨ぐ所属チェックは要求しない。

## 4. 後続へ延期するもの

- Partial trace。2026-10-27に一旦 future work とし、Step 5 の担当範囲と初期版の必須機能・検証項目から外した。数学的契約は将来の実装向けに保持する。
- 写像の表現行列・表現係数。2026-10-27に future work とし、共通 API、複数入力、入力ごとの共役指定、係数データの保持・再利用とその検証を延期した。状態・演算子の座標取得と密・疎 export は引き続き提供する。
- bra 型・構築 API と内部ラベル。braket は内積で計算し、grouping は既存の HilbertSpace を用いる。

- 異種局所構造を一つの系に混在・合成する機能と、そのための型消去・保持機構。
- Graded tensor product・fermion の実装。合成・作用・随伴・通常の trace に関する既存の数学的契約は保持する。
- Spin-1/2 以外の builtin algebra、1D Chain 以外の Geometry。
- source の自動保持、式の構造比較、および式表示 API。入力の不変性と不変実体の共有は維持する。
- 保存・復元、個別の簡約ルールを選択して適用する操作、評価結果のキャッシュ、並列評価・スレッド間共有。
- ML・自動微分 module、tensor network・MPS・MPO、GPU・分散計算などへの接続。
- 要件の 9 節にある部分空間・射影、因数分解、permutation など、既に対象外または将来候補として整理した機能。

Index の一意性・同一性、不変な実体の共有、および個別ルール適用を必要としない内部の分配・局所積・係数処理は維持する。延期対象を実装していないことを理由に、初期版の上記の完成条件を省略しない。

## 5. 残る実装設計

crate 分割と実装順序は、[実装計画](../implementation-plan.md)に定める。抽象契約・有限線型結合・共通式木・ジェネリックな Index の照合・空間・評価・基底処理は `qmb-core` に集約し、UUID の具体型と発行の `qmb-basic`、具体的代数の `qmb-spin-half`、幾何と Site への配置の `qmb-geometry`、数値変換の `qmb-export`、norm・状態の正規化の `qmb-normalize`、利用窓口の `qmb` と合わせて計画上は7 crate を構成する。basic・spin・export・normalize は core に依存し、spin の構築 utility は geometry の公開契約を利用する。core はそれらに依存しない。UUID・乱数源の依存は core に置かず、`no_std + alloc` を維持する。normalize は std を利用できる。

geometry は core に依存せず、両 crate に依存する qmb::space の ToSpace が空間変換を担当する。Chain の移行範囲と検証結果は[実装計画第9節](../implementation-plan.md#9-chain-の-index-列保持への移行)に従う。

式木には `ScaleExpr`・`SumExpr`・`ProductExpr`・`ActExpr`・`AdjointExpr` の共通パーツを用いる。`LinearCombination<P, C>` は薄い有限線型結合型として維持する。Step 2 で演算 trait を係数全体 `C` と関連型 `Term`・`Act::Operator` に揃え、core・spin-half の局所規則・恒等演算子・局所基底展開の線型結合を `map` と共通 constructor で式木へ取り込む。式全体の基底展開・複合基底・座標取得は Step 5 で実装する。不変な式節点・primitive は式ハンドルの `Arc` で共有し、同じハンドルを再利用した部分を複製しない。

LocalStructure は廃止し、式には S・O を直接指定する。恒等元は O の Identity、次元は primitive 型全体の SpanDimension とする。共通パーツは `expr::parts` で保持内容も公開し、式ハンドルを再公開する。節点 enum と共有の内部表現は非公開とする。項型 `Term<P, C>` は `ScaleExpr<P, C>` の別名に統合し、要素名を `operand` に揃える。既存の線型結合の構築・走査 API は維持する。`StateBasis`・`OperatorBasis` は削除し、状態には `Basis<S, C>`、演算子には `Basis<O, C>` を直接使う。次元からの基底要素数の取得と基底の数学的契約は維持する。

評価器は状態評価・演算子の作用・演算子項の走査を分担し、状態の作用評価に Product 能力を要求しない。型制約は必要な操作にだけ付け、演算子構文は所有値・借用値の4通りに対応する。評価と最後の所有者になった式節点の破棄は反復的に行う。長い式の評価・破棄、共有、不要な primitive 複製の抑制、空・単一項のコンテナ無確保を検証条件とし、map 全般の無確保や特定の実行時間は保証しない。

Step 3 の空間・複合式・共有・束縛・エラー・評価経路は [実装記録](../implementation-plan.md)に従う。局所規則は S・O と各能力の実装で定め、空間は `Arc` の共有ハンドルとし、総次元の overflow は取得時に検出する。状態は常に所属空間を持ち、演算子の束縛は外側のハンドルへ集約する。検証が必要な複合操作は `Result` を返し、作用・内積・full trace を目的別に評価する。

Norm・正規化・正規化期待値と NormalizationError は qmb-normalize に実装済みであり、[正規化 API の契約](primitive-expression.md#41-norm正規化の-api-と-feature)に従う。Norm／Normalize／NormalizedExpectation／NormalizedExpectationIn を import して呼び出す。内積・期待値・norm squared・スカラー除算は core に残し、Float は平方根を使う実数型 R に要求する。qmb の既定 feature は normalize、旧 libm はその互換 alias とし、core の libm feature は設けない。

XYZ・Heisenberg・Neel utility は qmb-spin-half に置き、qmb は再公開と縦断例を提供する。[Chain の配置契約](geometry.md)に従い、利用側が保持する空間へ接続する。基底処理は Step 5、数値 backend は Step 6 で具体化し、初期版の必須範囲を維持する。Partial trace は future work とし、初期版の必須範囲に含めない。bra 型・構築 API は初期版では導入しない。

Step 5 は [一時設計メモ](../step-5-design.md)の方針に従い、追加依存なしで実装済みである。`expand_in` は通常の式を返し、`coordinates_in` は独立した集約済みの疎な座標を返す。現在の公開 API と契約は[基底の設計第8節](basis.md#8-実装した公開-api2026-10-27)、検証結果は[実装計画第4.5節](../implementation-plan.md#45-段階5の実装検証状況)に記録する。Step 6 の数値 backend とその追加依存は同段階で選定する。段階1〜5の実装と初期版全体の完成とは区別し、数値 export とその受入確認は引き続き未実装とする。
