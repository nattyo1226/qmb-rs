# Index の契約

更新日: 2026-10-21

## 1. 対象と合意した契約

本書は、因子を識別する Index の発行、一意性の前提、再利用、局所状態・演算子への付与、保存・復元、複数ランタイム間での利用、および整合性検証の責任を定める。[アーキテクチャ概要](../architecture.md)における自由度・Hilbert 空間の設計の一部であり、site ID の具体的な生成方式は本書では定めない。

> Index は識別子のみを表し、局所構造とは独立に発行する。生成方式に基づいて一意性を仮定し、局所状態・演算子の作用先の識別と Hilbert 空間の因子順序の指定に使う。自由度は指定された Index と局所構造から構築する。両者の対応を全体で登録・固定する機構は設けず、合成・埋め込み・評価に必要な整合性は、その操作の対象から検証する。

## 2. Index と局所構造・自由度・空間

Index は、因子を照合するための不透明な識別子である。局所構造、次元、表示名、site 上の位置、基底、および tensor ordering を持たない。基底の座標を指定する数値的な index とも区別する。

| 対象 | 保持する情報と役割 |
| --- | --- |
| Index | 因子の同一性を表す識別子 |
| Index を付与した局所状態・演算子 | 元の局所構造と、所属先・作用先の因子を識別する Index |
| 自由度（Dof） | Index と局所構造の組 |
| Hilbert 空間 | 基本因子の Index と局所構造、因子順序、ordinary / graded の tensor 構造 |

Hilbert 空間は Factor・Tensor の再帰構造とし、自由度の Index は Factor に置く。Tensor の構築や既存因子の再利用で Index を追加・変更せず、重複は全階層の基本因子について検証する。部分系の取得操作は設けず、構築時に指定した空間・自由度を保持して利用する。詳細は [Hilbert 空間の再帰構造](hilbert-space.md)に定める。

同じ局所構造を持っていても、異なる Index を持つ自由度は独立した因子である。Index の一致と局所構造の一致は別に判定し、Index が一致することだけから局所構造が一致するとみなさない。局所構造は同じ定義・定義パラメータを持つ場合に一致とし、詳細は[局所構造の一致条件](local-structure.md#4-局所構造の一致条件)に定める。

初期版では一つの系の全基本因子を同じ局所構造型 `L` に揃え、異種局所構造の混在・合成は後続へ延期する。この制限は Index に局所構造を付加したり、Index と局所構造の対応を全体で固定したりするものではない。異なる局所構造を使う別々の系は、引き続き独立に構築できる。

## 3. 発行、構築、および局所状態・演算子への付与

Index の発行は、局所構造を指定せずに行う独立した操作とする。自由度を構築する操作には、発行済みの Index と局所構造を明示的に与える。

```text
Index の発行
    → Index と局所構造を指定して自由度を構築
    → 空間・状態・演算子などからその自由度を参照
```

自由度の構築は、与えられた Index を保持する。局所構造だけから自由度を構築し、その内部で Index を自動発行する経路は設けない。

局所状態・演算子には、発行済みの Index を明示的に付与して所属先・作用先を指定できる。元の局所構造はその局所状態・演算子が保持し、Index から取得しない。一つの局所自由度に属する未配置の局所式には、式全体に同じ Index を付与する。複数自由度の式は、それぞれの局所式に Index を付与してから合成する。

Index の付与は、spectator を含む全 Hilbert 空間への束縛とは別の操作である。付与だけでは全作用空間は確定せず、全作用空間への bind だけから各局所式の Index を推測しない。自由度の構築と局所式への付与のいずれも、新しい Index を暗黙に発行しない。

## 4. 一意性の前提

Index は UUID のように衝突確率が十分低い生成方式を用いて発行し、同一ランタイム内および複数ランタイム間で、独立に発行した Index の一意性を仮定する。この一意性は生成方式に基づく実用上の前提であり、数学的に衝突しないことの保証ではない。

共有採番器や、発行済み Index 全体を登録・照会する機構によって一意性を保証することは要求しない。具体的な生成方式・バージョンと、その実装に使うライブラリは未決とする。

この方針は、中央登録を必要とせずに実用的な一意性を得る UUID の考え方を参考にする。[RFC 9562 §6.8](https://www.rfc-editor.org/rfc/rfc9562.html#section-6.8)

## 5. Index の再利用と参照の共有

既存の自由度を利用するときは、同じ Index を保持する。ハンドルの複製、構築時に指定した自由度の再利用、およびその自由度への局所状態・演算子の配置によって、新しい Index を発行しない。具体的な共有所有の方式は本書では定めない。

| 操作 | Index の扱い |
| --- | --- |
| 独立した因子を用意する | 新しい Index を発行し、その Index で自由度を構築する |
| 既存の自由度のハンドルを複製する | Index を保持する |
| 構築時に指定した既存の自由度を再利用する | Index を保持する |
| 既存の自由度を状態・演算子の配置先として指定する | 指定した自由度の Index を付与する |

Index の意図的な再利用は、独立に発行した Index の偶発的な衝突とは区別する。同じ Index を持つ二つの自由度を、一つの tensor product に独立した因子として追加することは、基本因子の重複となる。同じ因子への複数の参照として Index を再利用することは許可する。

## 6. 局所構造との対応と整合性検証

Index と局所構造の対応を全体で登録・固定する機構は設けない。同じ Index を異なる局所構造と組み合わせた自由度の構築を、Index の既使用状況や過去の対応の照会によって拒否しない。

Index 単体から局所構造を取得できるという契約は置かない。自由度自身、局所状態・演算子、およびその自由度を含む空間が対応する局所構造を持ち、演算・検証に用いる。

Hilbert 空間の基本因子の順序は、Index の順序付き列で指定する。空間は各因子の局所構造と tensor product の種類・構造も保持し、Index の列だけでは空間は定まらない。Index の値の大小から順序を決めず、列の順序を用いる。たとえば異なる Index `i` と `j` について、`[i, j]` と `[j, i]` は異なる因子順序を表す。因子順序を変更する permutation は初期版ではサポートしない。

合成・埋め込み・評価では、対象となる自由度や空間が持つ情報を使って、以下を検証する。

- 空間の互換性は、基本因子の Index・順序・局所構造と、空・単因子 tensor product の同一視および同種の積の結合則を適用した後の tensor 構造に基づいて判定する。
- 空間・状態の tensor product は、同じ基本因子の Index が重複する場合に拒否する。親となる複合対象と内部因子の重複も含む。
- 演算子や状態が参照する Index の存在と、参照先の局所構造との整合性を検証する。
- 同じ自由度に作用する演算子同士の通常の積は許可する。

たとえば、同じ Index を spin-1/2 とユーザ定義の spin-1 のそれぞれに組み合わせた二つの自由度を、別々の系として構築できる。ただし、それらの系の合成・相互作用は初期版では扱わず、対応する因子として含む二つの空間も局所構造が一致しないため互換とみなさない。

判定できる情報が構築時に揃っていれば早期に検証し、全作用空間や評価 context に依存する条件は、その情報が得られる時点で検証する。これは Index と局所構造の対応を全体で管理することを要求しない。

## 7. 保存・復元と複数ランタイム

以下の三つの操作を区別する。

| 操作 | Index の扱い |
| --- | --- |
| 保存した対象を復元する | 元の Index とその参照関係を保持し、同じ自由度の記述を復元する |
| 保存した対象から独立した系を作る | 新しい Index を発行し、関連する空間・状態・演算子の参照を一貫して付け直す |
| 複数ランタイムから対象を持ち寄る | Index で因子を照合し、局所構造と空間の互換性を検証する |

### 7.1. 同じ自由度の記述の復元

復元によって新しい Index を発行しない。同じ保存対象を複数回復元した場合、同じ Index を持つ。メモリ上では別のオブジェクトでも、同じ自由度を指す記述として扱う。共有所有や同一のメモリ上のオブジェクトへの復元は要求しない。

二度の復元結果を独立した因子として一つの空間・状態の tensor product に追加すると、基本因子の Index が重複するため拒否する。同じ因子への複数の参照として利用することは許可する。

### 7.2. 独立した系の作成

保存した対象から独立した系を作る場合は、Index を保持する復元とは別に、明示的に新しい Index への対応を作る。同じ元 Index のすべての参照には同じ新 Index を割り当て、異なる元 Index には異なる新 Index を割り当てる。対象となる空間・状態・演算子の参照を一貫して付け直し、系内の参照関係を保持する。局所構造、因子順序、および tensor 構造はこの操作によって変更しない。

### 7.3. 複数ランタイムからの持ち寄り

別ランタイム由来でも、同じ Index は同じ因子を参照する記述として照合する。Index の一致だけで空間の互換性を認めず、6 節の条件を検証する。同じ Index に対する局所構造が一致しなければ、接続・比較時に不整合として扱う。対応を全体で登録・固定する機構は設けない。

異なる Index を、次元や物理的意味の一致だけから自動で対応づけない。独立した系として扱いたい場合は、7.2 節の明示的な付け直しを用いる。合成時の重複を避けるために Index を暗黙に変更しない。

計算上の内部 bond の処理によって qmb の Index を暗黙に変更しない。テンソルネットワークへの export では、物理自由度と計算上の脚の対応を別に設計する。

本節は同一性の設計契約を定めるものであり、保存機能や並列評価を初期版の必須実装に追加するものではない。

## 8. 未決事項

- Index の具体的な生成方式・バージョン、および採用する外部ライブラリ
- Index を表す Rust の型と、発行・自由度構築・局所状態や演算子への付与の公開 API
- 保存形式、および保存・復元・Index の付け直しの具体的な公開 API

これらの決定では、Index の独立した発行と、対応を全体で登録・固定する機構を設けない方針を維持する。
