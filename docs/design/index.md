# Index の契約

更新日: 2026-10-28

## 1. 対象と合意した契約

本書は、因子を識別する Index の発行、一意性の前提、再利用、局所状態・演算子への付与、保存・復元、複数ランタイム間での利用、および整合性検証の責任を定める。[アーキテクチャ概要](../architecture.md)における自由度・Hilbert 空間の設計の一部であり、site ID の具体的な生成方式は本書では定めない。

`qmb-core` は Index 型をジェネリックに受け取り、同一性の照合と局所式への付与・空間との整合性検証を担当する。UUID による具体的な Index 型と発行は `qmb-basic` に置く。`qmb-geometry` は外部の局所空間列から葉を借用するが、Chain 自体は Index 型を持たず、発行補助も提供しない。独立した自由度識別子は導入しない。

core が Index に要求する意味上の契約は「同じ Index であることを照合できる」こととする。同一性は安定した等価関係であり、照合するメソッドで標準の `Eq` を要求する。UUID の表現・生成、乱数源、seed、大小関係は core の契約に含めず、`Hash`・`Ord` や発行能力を一律に要求しない。保持・共有は空間・式のハンドルを複製することで行い、Index 本体の `Clone` は要求しない。

> Index は識別子のみを表し、局所構造とは独立に発行する。生成方式に基づいて一意性を仮定し、局所状態・演算子の作用先の識別と Hilbert 空間の因子順序の指定に使う。因子の構造は指定された Index から構築し、局所代数は式の primitive 型が定める。両者の対応を全体で登録・固定する機構は設けず、合成・埋め込み・評価に必要な整合性は、その操作の対象から検証する。

## 2. Index と局所構造・自由度・空間

Index は、因子を照合するための不透明な識別子である。局所構造、次元、表示名、site 上の位置、基底、および tensor ordering を持たない。基底の座標を指定する数値的な index とも区別する。

| 対象 | 保持する情報と役割 |
| --- | --- |
| Index | 因子の同一性を表す識別子 |
| Index を付与した局所状態・演算子 | primitive 型 S・O と、所属先・作用先の因子を識別する Index |
| 基本自由度（Factor） | Index を保持する Hilbert 空間の葉。独立した Dof 型は設けない |
| Hilbert 空間 | 基本因子の Index、因子順序、ordinary / graded の tensor 構造 |

Hilbert 空間は Factor・Tensor の再帰構造とし、自由度の Index は Factor に置く。自由度の構築は `HilbertSpace` の葉の構築を意味し、別の Dof オブジェクトは作らない。Tensor の構築や既存因子の再利用で Index を追加・変更せず、重複は全階層の基本因子について検証する。部分系の取得操作は設けず、構築時に指定した空間を保持して利用する。詳細は [Hilbert 空間の再帰構造](hilbert-space.md)に定める。

異なる Index を持つ因子は独立である。Index は局所代数の意味を定めず、S・O と各能力の実装が意味・規則を定める。空間構造の比較は Index と順序等を確認し、異種の式の不適切な合成は primitive と係数の型制約で拒否する。詳細は[局所 primitive の型契約](local-structure.md#4-局所構造の一致条件)に定める。

初期版では一つの系の全基本因子を同じ primitive 型 S・O に揃え、異種局所構造の混在・合成は後続へ延期する。この制限は Index に局所構造を付加したり、Index と局所構造の対応を全体で固定したりするものではない。異なる局所構造を使う別々の系は、引き続き独立に構築できる。

## 3. 発行、構築、および局所状態・演算子への付与

Index の発行は、局所構造を指定せずに行う独立した操作とする。因子を構築する操作には発行済みの Index を与える。

```text
Index の発行
    → Index を指定して HilbertSpace の葉を構築
    → 葉を空間の合成や状態・演算子の配置先として利用
```

自由度の構築は、与えられた Index を保持する。局所構造だけから自由度を構築し、その内部で Index を自動発行する経路は設けない。

局所状態・演算子には、発行済みの Index を明示的に付与して所属先・作用先を指定できる。primitive 型 S・O はその局所状態・演算子が保持し、Index から取得しない。一つの局所自由度に属する未配置の局所式には、式全体に同じ Index を付与する。複数自由度の式は、それぞれの局所式に Index を付与してから合成する。

Index の付与は、spectator を含む全 Hilbert 空間への束縛とは別の操作である。付与だけでは全作用空間は確定せず、全作用空間への bind だけから各局所式の Index を推測しない。自由度の構築と局所式への付与のいずれも、新しい Index を暗黙に発行しない。

Index の新規発行は利用側で明示的に行い、Chain は発行・保持しない。標準の Id128::default() は独立した Index を発行する。Clone／Copy は同じ識別値の複製であり、新規発行ではない。

Site 順の局所空間列を Chain とモデル構築へ借用して渡す。空間の共有と葉の列挙に Index の Clone は不要である。モデルと空間の構築は全葉の重複を Eq で検証する。詳細は[Chain の設計](geometry.md)に従う。

## 4. 一意性の前提

Index の提供側は、同一ランタイム内および複数ランタイム間で、独立に発行した Index の一意性を満たす責任を持つ。標準の具体実装は `qmb-basic` で UUID を用い、利用者による seed 指定を要求しない。この一意性は生成方式に基づく実用上の前提であり、数学的に衝突しないことの保証ではない。core は提供された Index の同一性を照合し、生成方式や一意性を自ら保証・検証しない。

共有採番器や、発行済み Index 全体を登録・照会する機構によって一意性を保証することは要求しない。UUID のバージョン・採用ライブラリ・発行 API は `qmb-basic` の実装設計で定める。UUID と乱数源に関する依存は core に持ち込まず、core の `no_std + alloc` を維持する。

この方針は、中央登録を必要とせずに実用的な一意性を得る UUID の考え方を参考にする。[RFC 9562 §6.8](https://www.rfc-editor.org/rfc/rfc9562.html#section-6.8)

## 5. Index の再利用と参照の共有

既存の自由度を利用するときは、同じ Index を保持する。ハンドルの複製、構築時に指定した自由度の再利用、およびその自由度への局所状態・演算子の配置によって、新しい Index を発行しない。具体的な共有所有の方式は本書では定めない。

| 操作 | Index の扱い |
| --- | --- |
| 独立した因子を用意する | 新しい Index を発行し、その Index で自由度を構築する |
| 既存の自由度のハンドルを複製する | Index を保持する |
| 構築時に指定した既存の自由度を再利用する | Index を保持する |
| 既存の自由度を状態・演算子の配置先として指定する | 指定した自由度の Index を付与する |

Index の意図的な再利用は、独立に発行した Index の偶発的な衝突とは区別する。同じ Index を持つ二つの自由度を、一つの tensor product に独立した因子として追加することは、基本因子の重複となる。同じ因子への複数の参照として Index を再利用することは許可する。

## 6. 局所構造との対応と整合性検証

Index と局所構造の対応を全体で登録・固定する機構は設けない。同じ Index を異なる局所構造と組み合わせた自由度の構築を、Index の既使用状況や過去の対応の照会によって拒否しない。

Index 単体や空間の葉から局所代数を取得する契約は置かない。式が S・O の型と能力実装により局所規則を定める。空間は因子の Index・順序・tensor 構造を保持する。

合成・配置・束縛では次を確認する。

- 空間の互換性・部分系判定は Index・順序と、空・単因子の同一視および同種の積の結合則に基づく。
- 空間・状態の tensor product は基本因子の Index が重複する場合に拒否する。
- 式が参照する Index の存在を確認し、状態・演算子の組合せは対応する S・O・C の型制約と評価時の能力で保証する。
- 同じ因子への演算子同士の積は許可する。

同じ因子構造を spin-1/2 と独自代数の式が独立に利用できる。このことは、その異なる primitive 型の式を同じ式に合成できることを意味しない。

判定できる情報が構築時に揃っていれば早期に検証し、全作用空間や評価 context に依存する条件は、その情報が得られる時点で検証する。これは Index と局所構造の対応を全体で管理することを要求しない。

## 7. 保存・復元と複数ランタイム

以下の三つの操作を区別する。

| 操作 | Index の扱い |
| --- | --- |
| 保存した対象を復元する | 元の Index とその参照関係を保持し、同じ自由度の記述を復元する |
| 保存した対象から独立した系を作る | 新しい Index を発行し、関連する空間・状態・演算子の参照を一貫して付け直す |
| 複数ランタイムから対象を持ち寄る | Index で因子を照合し、局所構造と空間の互換性を検証する |

### 7.1. 同じ自由度の記述の復元

復元によって新しい Index を発行しない。同じ保存対象を複数回復元した場合、同じ Index を持つ。メモリ上では別のオブジェクトでも、同じ自由度を指す記述として扱う。共有所有や同一のメモリ上のオブジェクトへの復元は要求しない。

二度の復元結果を独立した因子として一つの空間・状態の tensor product に追加すると、基本因子の Index が重複するため拒否する。同じ因子への複数の参照として利用することは許可する。

### 7.2. 独立した系の作成

保存した対象から独立した系を作る場合は、Index を保持する復元とは別に、明示的に新しい Index への対応を作る。同じ元 Index のすべての参照には同じ新 Index を割り当て、異なる元 Index には異なる新 Index を割り当てる。対象となる空間・状態・演算子の参照を一貫して付け直し、系内の参照関係を保持する。局所構造、因子順序、および tensor 構造はこの操作によって変更しない。

### 7.3. 複数ランタイムからの持ち寄り

別ランタイム由来でも、同じ Index は同じ因子を参照する記述として照合する。Index の一致だけで空間の互換性を認めず、6 節の条件を検証する。異種の式の不適切な接続は S・O・C と演算能力の制約で拒否する。対応を全体で登録・固定する機構は設けない。

異なる Index を、次元や物理的意味の一致だけから自動で対応づけない。独立した系として扱いたい場合は、7.2 節の明示的な付け直しを用いる。合成時の重複を避けるために Index を暗黙に変更しない。

計算上の内部 bond の処理によって qmb-rs の Index を暗黙に変更しない。テンソルネットワークへの export では、物理自由度と計算上の脚の対応を別に設計する。

本節は同一性の設計契約を定めるものであり、保存機能や並列評価を初期版の必須実装に追加するものではない。

## 8. 未決事項

同一性を照合するジェネリックな core と、UUID の具体型・seed 指定不要の発行を担う basic の分離は採用済みとする。葉の空間と式の共有ハンドルの複製に Index 本体の不要な複製を要求しない。

Core の照合は標準の `Eq`、Factor の構築は `HilbertSpace::factor(index)`、局所式の配置は `at(&factor)` とする。標準具体型 `qmb_basic::Id128` は UUID v4 を包む不透明な型であり、`new()` と `Default` は seed 指定不要で新しい Index を発行する。Clone・Copy は同一性を保持し、Display・Debug・等値比較・順序比較・Hash を提供する。生成は `uuid::Uuid::new_v4` に委譲し、乱数源が利用できない場合を含む挙動は同 API に従う。UUID・乱数源は basic に閉じ、Chain は basic に依存しない。

`qmb_basic::HilbertSpace` は `qmb_core::HilbertSpace<Id128>` の型別名とし、局所 primitive の型引数を持たない。Id128 は `qmb-basic`、ジェネリックな HilbertSpace は `qmb-core` から利用する。

後続の未決事項は以下とする。
- 保存形式、および保存・復元・Index の付け直しの具体的な公開 API

これらの決定では、Index の独立した発行と、対応を全体で登録・固定する機構を設けない方針を維持する。
