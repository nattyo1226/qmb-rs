# v3 に向けた実装案

作成日: 2026-10-30
更新日: 2026-10-31

v3 への更新の対象は以下の4項目とする。各項目の設計状況と採否は、以下および専用文書で管理する。

## 式木表示のカスタムフォーマット

`println!`・`format!` で式木を読みやすく表示できるよう、カスタムのフォーマット実装を検討する。

- `Display` による数式風の表示、`Debug` による構造表示、表示用ラッパーの役割を整理する。公開 API と具体的な書式は未確定とする。
- 和・積・係数・作用・随伴などの節点を区別し、演算の優先順位と括弧、因子順序、Index の表示方法を定める。必要に応じてインデント付きの複数行表示も検討する。
- 表示対象は保持している式木とし、表示のための暗黙の評価・展開・簡約は行わない。
- primitive・係数・Index に必要な表示能力は、表示 API の利用時に要求する。式の構築・評価に一律の `Display`・`Debug` 制約を追加しない。

検証では、入れ子の和・積、非可換な積、複素係数、零・単位元などの表示を確認し、括弧や順序が式の意味を誤って伝えないことを確かめる。

[今後の課題にある式の構造表示 API](../../future-work.md#2-延期した機能と検討事項)を具体化する候補として扱う。

## プロジェクトルートの README とライセンスファイル

プロジェクトルートに `README.md` とライセンスファイルを整備する。

- `README.md` には、プロジェクトの目的・提供機能、crate の構成、依存設定と feature、最小の利用例、examples・設計文書へのリンク、開発時のビルド・検証方法をまとめる。
- 実装済みの機能と将来の計画を区別し、利用例やコマンドは現行の公開 API・リポジトリ構成と一致させる。
- 採用ライセンス、著作権者表記、適用範囲を確定したうえで、対応するライセンスファイルを配置する。採用ライセンスは現時点では未定とする。
- ライセンス確定後、README の案内と workspace・各 crate の Cargo メタデータを整合させる。

検証では、README 内のリンク・利用例・コマンドと、ライセンスファイル・Cargo メタデータの対応を確認する。

## GitHub Actions の workflow 整備

`.github/workflows/` に継続的な検証のための workflow を整備する。現時点では同ディレクトリは存在しない。

- pull request・push 時に、format、Clippy、ビルド・テスト（doc test を含む）、ドキュメント生成を実行する。
- default feature 無効・全 feature 有効に加え、`qmb-export` の backend ごとの feature 構成を確認する。
- MSRV でのビルド・テストと、`no_std + alloc` 対応 crate の専用 target でのビルドを検討し、[未実施の検証](../../future-work.md#3-未実施の検証と性能)を補う。
- 対象ブランチ・OS・Rust toolchain、ジョブ分割、依存キャッシュ、実行時間を整理し、ローカルの検証手順と README の案内を一致させる。

具体的な workflow 構成は未確定とする。導入時には GitHub Actions 上での実行結果を確認し、実施できた検証と残る制約を記録する。

## 3体以上の相互作用に対応する関係の列挙

**設計採用済み・本体未実装（2026-10-31）**。

Geometry・Relation<G>・SiteMapper・MappedGroup により、幾何に基づく Site の配置を外部の space 列へ借用接続する。Site 数の取得名は num_sites、Relation のエラーは関連型 Error とし、旧 API の互換性は維持しない。

複数葉の標準操作は leaves_cartesian・leaves_zip とし、共通入口に combine_leaves(FnOnce) を設ける。一般の支持集合の組み合わせ列挙は geometry の Relation に含めず、正方格子の正式実装も今回の対象外とする。

採用設計・列挙規約・移行手順・検証記録は、[qmb-geometry のリファクタリング計画](geometry-refactoring.md)に集約する。
